11  深層強化学習（DQN）

11.1 本章のねらい

前章では、CartPole-v1 の連続状態を無理やり区間に分ける「離散化（Binning）」によって Qテーブルを作りましたが、状態の種類が増えると表が巨大化してパンクしてしまう「表形式の限界」があることを見ました。

本章の前半では、この限界を突破して現代のAIブームの火付け役となった深層強化学習（Deep Reinforcement Learning）の代表手法である DQN（Deep Q-Network） の考え方を、数式を使わずに直感的に理解し、CartPole-v1 を離散化なしで学習させる実験を行います。

後半のミニプロジェクト(2)では、前回作成した自作ゲームのプロトタイプを Gymnasium の標準規格（gymnasium.Env）に変換し、どの強化学習アルゴリズムからでも呼び出せる「自作強化学習環境」を完成させます。

11.2 Qテーブルからニューラルネットワークへ

11.2.1 「表で丸暗記する」のではなく「関数で予測する」

これまでの Q-learning は、状態 \(s\) と行動 \(a\) のすべての組み合わせについて、巨大な表（Qテーブル）を用意して1マスずつ値を書き込んでいました。これはいわば「過去に出た試験問題と答えを1問残らず丸暗記する」ような方法です。そのため、まだ一度も訪れたことがない状態（少しだけ角度や位置が違う状態）に出会うと、どう行動すべきかまったく分かりません。

そこで発想を転換し、巨大な表の代わりに第5回で学んだニューラルネットワーク（深層学習）を使います。

  • 入力：現在の状態 \(s\)（たとえば Cart Pole なら [位置, 速度, 角度, 角速度] という4つの小数をそのまま入力する）
  • 出力：その状態で選べる各行動の Q値（たとえば [左へ押すQ値, 右へ押すQ値]）

このように、ニューラルネットワークを使って行動価値 \(Q(s, a)\) を予測する手法を DQN（Deep Q-Network） と呼びます（2015年に Google DeepMind が発表し、ブロック崩しやインベーダーなどのテレビゲームを人間以上の腕前でプレイして世界を驚かせました）。

11.2.2 ニューラルネットワークを使う最大のメリット：「汎化（Generalization）」

ニューラルネットワークを使うと、状態を区間（ビン）に分ける離散化が一切不要になるだけでなく、「似たような状態なら、似たような Q値になるはずだ」と応用を利かせて予測する能力（汎化能力）が手に入ります。

たとえば「角度が \(+5.0^\circ\) のときに右へ押すと良かった」という経験を学べば、まだ一度も経験していない「角度が \(+5.1^\circ\) の状態」に出会ったときにも、ネットワークが自動的に「これも右へ押す価値が高いはずだ」と正しく推測してくれます。

ノート練習問題 11-01：Qテーブルと DQN の違い
  1. CartPole-v1 を学習させるとき、前章の「離散化 Q-learning」と本章の「DQN」では、4つの連続値の状態（位置・速度・角度・角速度）の扱い方にどのような違いがありますか？
  2. ニューラルネットワークを使うことで、まだ一度も訪れたことがない状態に対しても適切な行動を選べるようになる性質を何と呼びますか？

11.3 DQN を安定して学習させる2つの工夫

実は、Q-learning の「1歩進んだ先の見込み（最大Q値）を目標にして少しずつ修正する」という仕組みをそのままニューラルネットワークに適用すると、学習が不安定になってうまくいかないことが知られていました。DQN では、これを解決するために次の2つの直感的な工夫を取り入れています。

  1. 経験再生（Experience Replay）：「思い出ノート」からランダムに復習する
    • ゲームをプレイしながら、1歩ごとの経験 （状態, 行動, 報酬, 次の状態, 終了フラグ） を「思い出ノート（リプレイバッファ）」にどんどん溜めていきます。
    • 学習するときは、直前の1歩だけを見るのではなく、ノートに溜まった過去の経験の中からランダムに数十個を取り出してまとめて復習します。これにより、「最近の似たような場面ばかりに引きずられて、前に学んだ大事な場面を忘れてしまう」のを防ぐことができます。
  2. ターゲットネットワーク：「目標のゴールポスト」をしばらく固定する
    • Q-learning では「移動先の状態での最大Q値」を目標（お手本）にして現在の予測を修正しますが、同じ1つのネットワークで予測と目標の両方を計算すると、予測を修正するたびに目標自体も一緒に動いてしまい、自分の尻尾を追いかける犬のように値が暴走してしまいます。
    • そこで、お手本を計算するためのネットワーク（ターゲットネットワーク）を別にもう1つコピーして用意し、一定ステップの間は固定しておくことで、落ち着いた目標に向かって安定して学習できるようにします。
ノート練習問題 11-02：DQN の2つの工夫
  1. DQN において、直前の1ステップだけでなく過去の経験を溜めておいてランダムに取り出して学習する仕組みを何と呼びますか？また、それにはどのようなメリットがありますか？
  2. 目標値を計算するためのネットワークを一定期間固定しておくのは、どのような問題を防ぐためですか？

11.4 vibe coding：DQN による Cart Pole の学習と比較

それでは vibe coding によって、CartPole-v1 を離散化なしの DQN で学習させるプログラムを作成し、前章の離散化 Q-learning と学習の進み方や安定性を比較してみましょう。

11.4.1 作成するプログラムの仕様

  1. DQN エージェントの構築と学習:
    • "CartPole-v1" の4次元の連続状態をそのまま入力し、左右2つの行動の Q 値を出力するニューラルネットワーク（PyTorch または Stable-Baselines3 を使用）を構築する。
    • 経験再生とターゲットネットワークを用いて学習を行い、エピソードごとの獲得報酬（維持ステップ数）を記録する。
  2. 学習曲線の描画と実演テスト:
    • エピソード経過に伴う報酬の推移グラフを描画し、上限の 500 ステップに到達する様子を確認する。
    • 学習済みのモデルを使って Pygame 画面でカートを制御させ、離散化 Q-learning のときよりも滑らかに棒をピタリと中央で安定させられることを観察する。

11.5 ミニプロジェクト(2)：自作ゲームの Gymnasium 環境化

後半のミニプロジェクトでは、前回（第10回）作成した「人間が遊べる自作ゲームのプロトタイプ」を、Gymnasium の標準環境クラス（gymnasium.Env）へと作り替えます。

11.5.1 なぜ gymnasium.Env の形にするのか？

第9回で学んだとおり、Gymnasium の環境はすべて共通の命令（reset() と step(action)）で動くように統一されています。自分のゲームをこの規格に合わせて作成しておけば、これまで学んだ Q-learning も、今回学んだ DQN も、次回学ぶ方策勾配法（PPO）も、環境を差し替えるだけでそのまま自分のゲームに接続してAIを育てられるようになります。

11.5.2 gymnasium.Env クラスに必要な5つのパーツ

自作ゲームを Gymnasium 環境にするには、gym.Env を継承したクラスの中に以下の要素を用意します（コード自体は Antigravity に指示して作成してもらいます）：

  1. action_space（行動空間の定義）：AIが選べる行動の種類（例：3択なら spaces.Discrete(3)）。
  2. observation_space（状態空間の定義）：AIに観測させる状態の形式や範囲（例：マス目番号なら spaces.Discrete(25)、複数の連続値なら spaces.Box(...)）。
  3. reset() メソッド：ゲームを初期状態に戻し、初期状態, info を返す。
  4. step(action) メソッド：AIが選んだ action に従ってゲームを1ステップ進め、次の状態, 報酬, terminated, truncated, info の5つを返す。
  5. render() メソッド：現在のゲームの画面を描画する。

11.5.3 vibe coding：自作ゲームの Env 化とランダムAIによる動作テスト

Antigravity に対して、前回作成したゲームのプロトタイプを gymnasium.Env を継承したクラス（例：my_game_env.py）に変換するよう指示します。さらに、変換した環境が正しく動くかを確かめるテストプログラムを作成し、ランダムに行動を選ぶAI（env.action_space.sample()）に100エピソード遊ばせて以下をチェックします：

  • エラーで止まることなく100エピソード最後まで完走できるか？
  • 状態（obs）の数値が observation_space で定義した範囲内に収まっているか？
  • ゲームクリアやゲームオーバーのときに正しく報酬が与えられ、terminated または truncated が True になってエピソードが終了するか？
ノート練習問題 11-03：自作環境のインターフェース確認

あなたが作成した自作ゲームの Env クラスについて、次の点を確認して答えてみましょう。

  1. action_space と observation_space はそれぞれどのような型・サイズに設定されていますか？
  2. ランダム方策のエージェントで100エピソード実行したとき、1エピソードあたりの平均報酬や平均ステップ数はいくらになりましたか？（この数値が、次回AIを学習させたときにどれだけ賢くなったかを測る「基準（ベースライン）」になります！）

11.6 まとめ

  • DQN（Deep Q-Network）: Qテーブルの代わりにニューラルネットワークを使って状態から各行動のQ値を予測する手法。連続状態をそのまま入力でき、似た状態へ知識を応用する汎化能力を持つ。
  • 経験再生とターゲットネットワーク: 過去の経験をランダムに復習する「経験再生」と、目標計算用のネットワークを一定期間固定する「ターゲットネットワーク」により、ニューラルネットワークの学習を安定させる。
  • ミニプロジェクトの環境化: 自作ゲームを gymnasium.Env の規格（reset, step 等）に統一することで、あらゆる強化学習アルゴリズムをそのまま適用できる実験環境が完成する。

### なぜ `gymnasium.Env` の形にするのか？

第9回で学んだとおり、Gymnasium の環境はすべて共通の命令（`reset()` と `step(action)`）で動くように統一されています。自分のゲームをこの規格に合わせて作成しておけば、**これまで学んだ Q-learning も、今回学んだ DQN も、次回学ぶ方策勾配法（PPO）も、環境を差し替えるだけでそのまま自分のゲームに接続してAIを育てられる**ようになります。

### `gymnasium.Env` クラスに必要な5つのパーツ

自作ゲームを Gymnasium 環境にするには、`gym.Env` を継承したクラスの中に以下の要素を用意します（コード自体は Antigravity に指示して作成してもらいます）：

1. **`action_space`（行動空間の定義）**：AIが選べる行動の種類（例：3択なら `spaces.Discrete(3)`）。
2. **`observation_space`（状態空間の定義）**：AIに観測させる状態の形式や範囲（例：マス目番号なら `spaces.Discrete(25)`、複数の連続値なら `spaces.Box(...)`）。
3. **`reset()` メソッド**：ゲームを初期状態に戻し、`初期状態, info` を返す。
4. **`step(action)` メソッド**：AIが選んだ `action` に従ってゲームを1ステップ進め、`次の状態, 報酬, terminated, truncated, info` の5つを返す。
5. **`render()` メソッド**：現在のゲームの画面を描画する。

### vibe coding：自作ゲームの `Env` 化とランダムAIによる動作テスト

Antigravity に対して、前回作成したゲームのプロトタイプを `gymnasium.Env` を継承したクラス（例：`my_game_env.py`）に変換するよう指示します。さらに、**変換した環境が正しく動くかを確かめるテストプログラム**を作成し、ランダムに行動を選ぶAI（`env.action_space.sample()`）に100エピソード遊ばせて以下をチェックします：

- エラーで止まることなく100エピソード最後まで完走できるか？
- 状態（`obs`）の数値が `observation_space` で定義した範囲内に収まっているか？
- ゲームクリアやゲームオーバーのときに正しく報酬が与えられ、`terminated` または `truncated` が `True` になってエピソードが終了するか？

## まとめ

- **DQN（Deep Q-Network）**: Qテーブルの代わりにニューラルネットワークを使って状態から各行動のQ値を予測する手法。連続状態をそのまま入力でき、似た状態へ知識を応用する**汎化能力**を持つ。
- **経験再生とターゲットネットワーク**: 過去の経験をランダムに復習する「経験再生」と、目標計算用のネットワークを一定期間固定する「ターゲットネットワーク」により、ニューラルネットワークの学習を安定させる。
- **ミニプロジェクトの環境化**: 自作ゲームを `gymnasium.Env` の規格（`reset`, `step` 等）に統一することで、あらゆる強化学習アルゴリズムをそのまま適用できる実験環境が完成する。
