5  機械学習

5.1 人工知能と機械学習の関係

5.1.1 人工知能とは

人工知能（AI: Artificial Intelligence）とは、人間の知的な振る舞い（認識、推論、学習、言語理解、意思決定など）をコンピュータ上で模倣・再現する技術全般を指す広範な概念です。

1950年代のチェスプログラムや論理パズルを解くシステム、1980年代の専門家の知識をルールとして教え込んだエキスパートシステムなどもすべて人工知能に含まれます。

そして、「機械学習」は人工知能の中に含まれる中核的な一分野です。

5.1.2 従来のコンピュータシステムと機械学習による問題解決の比較

これまでのプログラミングと機械学習では、問題に対するアプローチが根本から逆転しています。

  • 従来のコンピュータシステム（ルールベース）: 人間が問題のルール（手順・条件分岐）を隅々まで理解し、それをソースコードとして記述します。コンピュータはそのルールにデータを当てはめて「答え」を出力します。

  • 機械学習による問題解決: ルールを人間が手で書くことが困難な複雑な問題（例: 写真に写っているのが猫かどうか判定する）に対し、大量の「データ」をコンピュータに入力します。コンピュータがデータ間の相関関係や特徴を自動的に解析し、問題解決のための「ルール（学習済みモデル）」そのものを自ら生成します（この工程を学習または訓練と呼びます）。

    そして、一度完成した「学習済みモデル」に未知の新しいデータを入力すると、獲得したルールに基づいて「これは猫である（確率95%）」といった答えを予測・判定します（この工程を推論または予測と呼びます）。このように、機械学習は「データからモデルを作る段階（学習）」と「モデルを使って答えを出す段階（推論）」の2段階で動作します。

5.1.3 機械学習の3大分類

機械学習は、学習データの与えられ方や目的によって大きく3つの領域に分類されます。

分類 特徴 学習の手がかり 主なタスク・具体例
教師あり学習
(Supervised Learning)		 入力データと正解ラベルのペアから入出力関係を学ぶ 正解データ（ラベル） 画像認識、売上予測、迷惑メールフィルタ
教師なし学習
(Unsupervised Learning)		 正解のないデータから潜在的な構造やグループを発見する データ自体の類似度・分布 顧客クラスタリング、次元削減（PCA）、異常検知
強化学習
(Reinforcement Learning)		 試行錯誤しながら累積報酬を最大化する行動ルールを学ぶ 行動の結果得られる「報酬」 ゲームプレイAI、ロボット制御、自動運転

5.1.4 機械学習に使われる技術

機械学習には、目的に応じて様々なアルゴリズムや数学的モデルが使われます。ここでは代表的な手法とそれぞれの簡単な例を紹介します：

  • 決定木（Decision Tree）:
    • 概要: 「質問と分岐」を木構造（ツリー状）に繰り返して分類や予測を行う直感的なモデル。判断の根拠がフローチャートのように可視化されるため、なぜその結論に至ったかを人間が理解しやすい（解釈性が高い）利点があります。
    • 例（銀行の融資審査）: 過去の融資に関するデータを基に「年収は基準以上か？」「勤続年数は3年以上か？」といった無事に返済できるための条件を求め、その分岐をたどることで「融資可能 / 不可能」を判定します。
ノート練習問題 05-01：決定木の復習

「情報基礎１」でやった決定木の演習を思い出してください。どのようなデータを基に、どのような質問を選び、どのような木構造ができましたか？

  • サポートベクターマシン（SVM: Support Vector Machine）:

    • 概要: 異なるクラスを分ける「境界線（境界面）」を引く際、各グループの最も境界に近いデータ点との距離（マージン）が最大になるように決定する頑健な手法。境界近くのデータがうまく分離できるように境界を決めるので、未知のデータに対しても判定がブレにくい特徴があります。

    • 例（迷惑メールの自動分類）: メッセージに含まれる単語（例: 「当選」「無料」など）の出現頻度をもとに、通常メールと迷惑メールを分ける境界線を引きます。数千次元から数万次元という高次元空間の中で境界（超平面）を決めるため、誤判定の少ない高精度なフィルタリングが可能です。

  • ニューラルネットワーク（Neural Network）:
    • 概要: 人間の脳の神経細胞（ニューロン）のネットワーク構造を数理モデル化したもの。入力層・中間層・出力層からなり、シナプス結合の強さ（重み）を調整しながら複雑なパターンを学習します（中間層を多層に深く重ねたものが「深層学習（ディープラーニング）」です）。
    • 例（手書き数字の認識）: 手書きされた数字の画像（例: 28×28ピクセル）を入力層に渡し、中間層で「縦の直線」「丸み」「交差」といった特徴を捉え、出力層で「0〜9のどの数字であるか」を判定します。
ノート練習問題 05-02：ニューラルネットワークの復習

「情報基礎１」でやったTeachable Machineの演習を思い出してください。どのようなデータを入力して、どのような出力が出ましたか？精度はどうでしたか？

  • クラスタリング（Clustering）:

    • 概要: 正解ラベル（事前のカテゴリやグループ名）が与えられていないデータに対し、データ間の類似度に基づいて似た特徴を持つもの同士を自動的にグループ（クラスタ）分けする教師なし学習の代表的な手法。代表的なアルゴリズムである「\(k\)-means法（\(k\)平均法）」では、あらかじめ指定したグループ数（\(k\)個）にデータを分割し、各グループの中心（重心）との距離が近くなるようにデータを割り当てます。

    • 例（購買データによる顧客セグメンテーション）: 顧客の「年間の購入額」や「来店頻度」といったデータから、「たまに高額商品を買う層」「セール時にまとめ買いする層」などの類似した特徴を持つグループを自動的に見つけ出し、それぞれの顧客層に合わせたおすすめ商品やキャンペーンの企画に役立てます。

  • 拡散モデル（Diffusion Model）:

    • 概要: 物理学における「熱拡散（インクが水中に広がる現象）」の数理モデルに着想を得た深層生成モデル（Generative Model）。クリアなデータに徐々にノイズ（雑音）を加えて完全なランダムノイズにする「前向き過程（拡散）」と、ニューラルネットワークが各段階のノイズを予測して少しずつ取り除く（デノイズする）「逆過程（生成）」の2つで構成されます。学習済みのモデルは、純粋なノイズから高品質な画像などを復元・生成できます。

    • 例（画像生成AIなど）: Stable DiffusionやMidjourney、DALL-E 3などの画像生成AIの中核技術として広く利用されています。「夕暮れの海岸を走る猫」といったプロンプト（テキスト指示）を与えると、AIは完全なランダムノイズ（何の意味もない砂嵐）からスタートし、指示の内容に沿うようにノイズを数十ステップかけて少しずつ削り落としながら、高精細で新しい画像を生成します。画像にとどまらず、動画生成（Soraなど）や音声合成、創薬分野での新しい分子構造の設計などにも応用されています。

5.2 強化学習の特徴

強化学習（Reinforcement Learning）は、3大分類の中でも際立ったユニークな立ち位置を持っています。

5.2.1 他の機械学習との違い

  • 教師あり学習との比較: 「この局面ではこの手を打つのが正解」という模範解答（正解ラベル）は与えられません。与えられるのは「ゲームに勝った（+1）」「崖から落ちた（-100）」という結果としての報酬（Reward）の数値データだけです。
  • 教師なし学習との比較: データの背後にあるパターンをただ見つけるだけでなく、「どう行動すれば最も報酬を多く獲得できるか」という明確な目標が存在します。
  • 試行錯誤（Trial and Error）と探索: エージェントは、環境の中で自ら行動を起こし、成功や失敗の経験を積み重ねることで、どの状況（状態）でどの行動を選択すべきかという方策（Policy）を自律的に学習していきます。

5.2.2 生物における強化学習の例：犬の「お手」

人間や動物などの生物も、生来「強化学習」の仕組みを脳内に備えています。

身近で分かりやすい例が、犬に「お手」を教えるしつけ（オペラント条件づけ）です：

  • 行動と報酬の結びつき: 最初は飼い主が「お手」と言っても、犬は何をしてよいか分かりません。しかし、偶然にでも飼い主の手に前足を乗せる（行動する）と、飼い主から褒められ、大好きな餌（報酬）がもらえます。
  • 試行錯誤を通じた方策の獲得: 犬は「『お手』と言われた状況で前足を差し出すと、報酬（餌）が得られる」という経験を繰り返すことで、自発的にその行動をとるようになります。逆に、関係のない行動（あくびをする、吠えるなど）をしても報酬は得られません。犬は試行錯誤を通じて「どの状況でどう行動すれば報酬を得られるか」という行動ルール（方策）を学習しています。
  • 脳の仕組みと強化学習: 脳科学の研究では、動物や人間の脳内において神経伝達物質（ドーパミン）が「予想していた報酬」と「実際に得られた報酬」の差（報酬予測誤差）を計算し、良い結果をもたらした行動パターンを脳内で強化（定着）させることが明らかになっています。人工知能の強化学習は、まさにこの生物の「行動・試行錯誤・報酬」による学習メカニズムを数理モデル化したものです。

5.2.3 強化学習の成功例：AlphaGo から AlphaZero へ

強化学習が一躍世界的な脚光を浴びた歴史的な契機が、DeepMind社が開発した囲碁AIです。

  • AlphaGo（アルファ碁）:
    • 2016年に世界トップ棋士に勝利し、世界中に衝撃を与えました。
    • まず約3,000万手におよぶ人間のプロ棋士の対局データ（棋譜）を教師あり学習で学んだ後、強化学習（自分自身との対局＝自己対局）を何千万回も繰り返すことで、人間の直感を超える新手を編み出し、人類最強の打ち手を超越しました。
  • AlphaZero（アルファゼロ）:
    • AlphaGoの成功をさらに推し進め、2017年に登場した次世代AIです。
    • 人間の棋譜や定石などの知識を一切使わず、ゲームの基本ルールだけを与えられて学習を開始しました。白紙の状態（ゼロ）から純粋な強化学習（自己対局の試行錯誤のみ）だけで打ち方を学び、わずか数十時間の学習でAlphaGoを破る強さに到達しました。さらに、同じ仕組みで将棋やチェスでも世界最強の座を獲得しました。
    • 「人間の過去の知識に頼らずとも、強化学習の試行錯誤だけで人間を超える知能を自律的に獲得できる」ことを示した記念碑的な成果です。

5.3 バージョン管理システム（git）の導入

5.3.1 バージョン管理システムとは

バージョン管理システム（VCS: Version Control System）とは、ファイルの変更履歴（「いつ」「誰が」「どこを」「なぜ」変更したか）を体系的に記録・管理するためのシステムです。

レポート作成やプログラミングを行っていると、過去の状態を残しておこうとして次のようなファイル名を作ってしまった経験はないでしょうか：

  • report.txt
  • report_v2.txt
  • report_最終版.txt
  • report_本当に最終版.txt
  • report_提出用_修正2.txt

このような手作業によるファイル管理では、「どれが本当に最新なのか」「過去のバージョンと具体的にどこが違うのか」がすぐに分からなくなってしまいます。また、誤って上書き保存してしまい元の正常な状態に戻せなくなるといった事故も起こりがちです。

バージョン管理システムを導入すると、ファイル名は1つのままで、過去のあらゆる変更履歴（スナップショット）が安全に保存されます。いつでも過去の任意の時点の状態に復元したり、変更前後の差分を正確に比較したりできます。現在、世界中のソフトウェア開発で標準として使われている代表的なバージョン管理システムがGit（ギット）です。

5.3.2 バージョン管理システムの仕組み

Gitは、ファイルの変更履歴をゲームの「セーブデータ」のように、特定時点の状態（スナップショット）の連なりとして管理します。

Gitの内部では、主に以下の3つの領域を行き来しながら記録を進めます：

  1. 作業ツリー（ワークツリー / Working Tree）: 実際にファイルを編集したりプログラムを実行したりする、普段の作業フォルダです。
  2. ステージングエリア（インデックス / Staging Area）: 次にセーブ（コミット）したい変更を選んで載せる「準備台」です。編集したファイルのうち、今回の記録に含めたい変更だけを git add で登録します。
  3. リポジトリ（Repository）: 確定した変更履歴が永続的に保存される「記録庫（セーブデータの保管場所）」です。git commit を実行すると、ステージングエリアの内容にメッセージ（変更の意図）を添えた新しいセーブポイント（コミット）が作成され、履歴ツリーに記録されます。

このように、「編集する（作業ツリー） → セーブ対象を選ぶ（ステージング） → セーブする（リポジトリ）」という明確なステップを踏むことで、必要な単位ごとに整然と履歴を残し、万が一の際にはリポジトリから過去の状態を作業ツリーに復元（ロールバック）することができます。

ノートコラム：GitHubとチーム開発 — クラウドで広がる共同開発の仕組み

ここまでは個人のPC上で行うGitの基本操作を紹介しましたが、Gitが真価を発揮するのは複数人でのチーム開発です。

チーム開発では、各自のPC内にある「ローカルリポジトリ」に加え、インターネット上のクラウドサービスに「リモートリポジトリ」を置いて全員で共有します。その世界最大のプラットフォームがGitHub（ギットハブ）です。

  • プッシュ（push）とプル（pull）: 手元で作成したコミット履歴をリモートリポジトリに送信することを「プッシュ（git push）」、他のメンバーが更新した最新の履歴を手元に取り込むことを「プル（git pull）」と呼びます。
  • ブランチ（Branch / 枝分かれ）: 本番のコード（main ブランチ）に直接変更を加えるのではなく、新機能の開発やバグ修正ごとに作業の「枝分かれ」を作って作業できます。これにより、複数のメンバーが互いの作業を邪魔することなく同時に並行開発を進められます。
  • プルリクエスト（Pull Request / PR）とコードレビュー: 自分のブランチでの開発が完了したら、「本体のコードに合流（マージ）してください」とメンバーに提案するのがプルリクエストです。合流前に他の開発者がコードの内容を確認（レビュー）し、コメントや改善提案をやり取りすることで、バグを未然に防ぎ高い品質を維持します。
  • コンフリクト（競合）の防止と解決: もし複数人が同じファイルの同じ行を同時に変更してしまった場合、Gitは上書きせずに「コンフリクト（競合）」として警告を発します。どちらの変更を採用すべきか人が確認して統合できるため、誰かの作業を誤って消去してしまう事故を防ぎます。

世界中のオープンソースプロジェクト（Python自体や、PyTorch、VS Codeなど）も、このGitHub上で世界各国の開発者が協力しながら日々開発・改善されています。

5.3.3 なぜAntigravityでの開発にgitが便利なのか？

次回以降の教材では、いよいよcoding agent（Antigravity等）と対話しながら自律エージェントのプログラムを作成していきます。

ここで極めて重要になるのが、このバージョン管理システム「git」の活用です。

  1. 変更履歴の自動追跡と安心感: coding agentに「〇〇の機能を追加して」「〇〇のバグを修正して」と指示すると、エージェントは複数のファイルを一度に変更します。gitを使っていれば、エージェントがどの行を書き換えたのかがすべて色付きで明瞭に確認できます。
  2. いつでも元の状態に戻せる（タイムマシン機能）: エージェントの修正によってプログラムが動かなくなってしまったり、方針を変えたくなった場合でも、git checkout や git restore コマンドで一瞬にして直前の正常な状態に戻すことができます。試行錯誤を恐れずに大胆な開発が行えます。
  3. 作業の区切り（コミット）の記録: 「環境の作成完了」「学習ループの実装」「グラフ表示機能の追加」といったマイルストーンごとにコミット（記録）を残すことで、開発の進捗が整理されます。

まず、パソコンにGitがインストールされているか確認し、初回のみ必要なユーザー情報を設定します。

ターミナル（Windowsの場合はPowerShellまたはGit Bash）を開き、以下のコマンドを実行します：

git --version
  • バージョン番号（例: git version 2.40.0）が表示されれば、すでにインストールされています。
  • macOS: コマンドを入力した際に「コマンドライン開発者ツールが必要です」とダイアログが出た場合は、「インストール」を選択して導入します。
  • Windows: 未インストールの場合は、Git for Windows（gitforwindows.org） からインストーラをダウンロードしてセットアップします。

なお、インストール時に一緒に導入される 「Git Bash」 を使用しても構いません。Git BashはmacOSと同じUNIX系のコマンド体系（Bash）で動作するため、Macと同じ操作感で進めたい場合はこちらも利用できます。

5.3.4.2 作業フォルダの準備とリポジトリの作成（git init）

実習用の作業フォルダを作成し、Gitの管理下に置きます（リポジトリの初期化）。

# 実習用の作業フォルダを作成して移動
mkdir git_practice
cd git_practice

# Gitリポジトリとして初期化
git init

実行すると、フォルダ内に隠しフォルダ .git/ が生成され、このフォルダ全体がGitの「作業ツリー」として管理されるようになります。

5.3.4.3 ファイルの作成（.py と .md）

プロジェクトで使うPythonスクリプトと、その内容を説明するMarkdownファイルを作成します。

エディタ等を使って、以下の2つのファイルを作成・保存してください：

  • hello.py（Pythonプログラム）:

    # 動作確認用のスクリプト
print("強化学習エージェントへようこそ！")

  • README.md（プログラムの説明ファイル）:

    # 強化学習プロジェクト
自律エージェントを作成・学習させるためのプロジェクトです。

ファイルを作成したら、現在のGitの状態を確認してみましょう：

git status

出力結果の Untracked files（未追跡のファイル）欄に、赤字などで hello.py と README.md が表示されます。これは「新しいファイルが作成されたが、まだGitの記録対象（ステージングエリア）に載っていない」状態を示しています。

5.3.4.4 最初のコミット

作成した2つのファイルをステージングエリア（準備台）に載せ、最初のセーブポイント（コミット）を作成します。

# 1. 作成したファイルをステージングエリアに追加
git add hello.py README.md
# （フォルダ内の全変更をまとめて追加する場合は git add . でも可能です）

# 2. 状態を確認
git status

Changes to be committed（コミット予定の変更）として緑色で表示され、セーブの準備が整ったことが分かります。

# 3. メッセージを添えてコミットを実行
git commit -m "初期作成: hello.pyとREADME.mdを追加"

これで、現在の2つのファイルの状態がリポジトリに永久保存されました。 履歴を確認してみましょう：

git log --oneline

コミットのID番号とともに、指定したメッセージが1件表示されます。

5.3.4.5 ファイルの修正

続いて、プログラムに機能を追加し、説明ドキュメントを更新してみましょう。

  • hello.py を次のように書き換えて保存します：

    # 動作確認用のスクリプト
def greet(name):
    print(f"強化学習エージェント {name} へようこそ！")

greet("Antigravity")

  • README.md に実行方法の記述を追記して保存します：

    # 強化学習プロジェクト
自律エージェントを作成・学習させるためのプロジェクトです。

## 実行方法
`python hello.py` を実行してください。

ファイルを保存した後、git status を実行すると、modified: hello.py および modified: README.md と表示され、ファイルが変更されたことをGitが自動検知していることが確認できます。

5.3.4.6 2回目のコミット

変更内容を2つ目のセーブポイントとして記録します。

# 変更したファイルをステージング
git add .

# 2回目のコミットを実行
git commit -m "挨拶関数を定義し、READMEに実行方法を追記"

再度 git log --oneline を実行すると、コミット履歴が2件に増え、時系列順に積み重なっていることが確認できます。

5.3.4.7 diffの確認（差分の確認）

Gitの大きな強みは、「過去と現在」や「作業中の修正内容」の差分（どこを書き換えたか）を正確に比較できることです。

  1. コミット間の差分を確認する: 直前のコミット（1つ前）と最新のコミットの間でどのような変更が行われたかを確認するには、以下を実行します：

    git diff HEAD~1 HEAD

    追加された行が緑色（+）、削除された行が赤色（-）で表示され、変更内容が一目で分かります。

  2. 作業中の差分を確認する: ファイルを編集した直後（まだ git add や git commit をしていない段階）に git diff を実行すると、最後のコミットからの変更点を確認できます。coding agentがファイルを修正した直後にこのコマンドを実行すれば、エージェントが「どのファイルのどこを変更したのか」を確実に把握できます。

5.3.4.8 前の状態に戻す（変更の取り消し・ロールバック）

試行錯誤中に誤ったコードを書いてしまいプログラムが動かなくなったり、ファイルを壊してしまった場合でも、直前のセーブポイントの状態に一瞬で復元できます。

例えば、hello.py の中身を適当にいじって壊してみたり、誤って削除してしまったとします。

まだコミットしていない作業ツリーの変更を取り消し、直前のコミット状態に元通り復元するには、以下のコマンドを実行します：

git restore hello.py

（フォルダ全体の変更をまとめて元に戻したい場合は git restore .）

エディタで hello.py を開き直すと、誤った変更が綺麗に取り消され、直前の正常に動作していた状態に復元されていることが確認できます。

ヒント過去の特定のコミットの状態に戻したい場合

もし「直前」ではなく「2つ前」など過去の特定のコミットの状態を確認したり戻したりしたい場合は、git restore --source=HEAD~1 hello.py のように特定のコミットを指定して復元するか、git checkout コミットID などを使って過去の時点を閲覧・切り替えることができます。

  2. 最後のコミットと、現在のファイル内容の差分を表示してください。

### 従来のコンピュータシステムと機械学習による問題解決の比較
これまでのプログラミングと機械学習では、問題に対するアプローチが根本から逆転しています。

- **従来のコンピュータシステム（ルールベース）**:
  人間が問題のルール（手順・条件分岐）を隅々まで理解し、それをソースコードとして記述します。コンピュータはそのルールにデータを当てはめて「答え」を出力します。
- **機械学習による問題解決**:
  ルールを人間が手で書くことが困難な複雑な問題（例: 写真に写っているのが猫かどうか判定する）に対し、大量の「データ」をコンピュータに入力します。コンピュータがデータ間の相関関係や特徴を自動的に解析し、**問題解決のための「ルール（学習済みモデル）」そのものを自ら生成**します（この工程を**学習**または訓練と呼びます）。

  そして、一度完成した「学習済みモデル」に未知の新しいデータを入力すると、獲得したルールに基づいて「これは猫である（確率95%）」といった**答えを予測・判定**します（この工程を**推論**または予測と呼びます）。このように、機械学習は「データからモデルを作る段階（学習）」と「モデルを使って答えを出す段階（推論）」の2段階で動作します。

### 機械学習の3大分類
機械学習は、学習データの与えられ方や目的によって大きく3つの領域に分類されます。

| 分類 | 特徴 | 学習の手がかり | 主なタスク・具体例 |
| :--- | :--- | :--- | :--- |
| **教師あり学習**<br>(Supervised Learning) | 入力データと正解ラベルのペアから入出力関係を学ぶ | 正解データ（ラベル） | 画像認識、売上予測、迷惑メールフィルタ |

| **強化学習**<br>(Reinforcement Learning) | 試行錯誤しながら累積報酬を最大化する行動ルールを学ぶ | 行動の結果得られる「報酬」 | ゲームプレイAI、ロボット制御、自動運転 |

### 機械学習に使われる技術
機械学習には、目的に応じて様々なアルゴリズムや数学的モデルが使われます。ここでは代表的な手法とそれぞれの簡単な例を紹介します：

- **決定木（Decision Tree）**:
  - **概要**: 「質問と分岐」を木構造（ツリー状）に繰り返して分類や予測を行う直感的なモデル。判断の根拠がフローチャートのように可視化されるため、なぜその結論に至ったかを人間が理解しやすい（解釈性が高い）利点があります。
  - **例（銀行の融資審査）**: 過去の融資に関するデータを基に「年収は基準以上か？」「勤続年数は3年以上か？」といった無事に返済できるための条件を求め、その分岐をたどることで「融資可能 / 不可能」を判定します。

## 強化学習の特徴

強化学習（Reinforcement Learning）は、3大分類の中でも際立ったユニークな立ち位置を持っています。

### 他の機械学習との違い
- **教師あり学習との比較**:
  「この局面ではこの手を打つのが正解」という模範解答（正解ラベル）は与えられません。与えられるのは「ゲームに勝った（+1）」「崖から落ちた（-100）」という結果としての**報酬（Reward）**の数値データだけです。
- **教師なし学習との比較**:
  データの背後にあるパターンをただ見つけるだけでなく、「どう行動すれば最も報酬を多く獲得できるか」という明確な目標が存在します。
- **試行錯誤（Trial and Error）と探索**:
  エージェントは、環境の中で自ら行動を起こし、成功や失敗の経験を積み重ねることで、どの状況（状態）でどの行動を選択すべきかという**方策（Policy）**を自律的に学習していきます。

### 生物における強化学習の例：犬の「お手」
人間や動物などの生物も、生来「強化学習」の仕組みを脳内に備えています。

身近で分かりやすい例が、**犬に「お手」を教えるしつけ（オペラント条件づけ）**です：

- **行動と報酬の結びつき**:
  最初は飼い主が「お手」と言っても、犬は何をしてよいか分かりません。しかし、偶然にでも飼い主の手に前足を乗せる（**行動する**）と、飼い主から褒められ、大好きな餌（**報酬**）がもらえます。
- **試行錯誤を通じた方策の獲得**:
  犬は「『お手』と言われた状況で前足を差し出すと、報酬（餌）が得られる」という経験を繰り返すことで、自発的にその行動をとるようになります。逆に、関係のない行動（あくびをする、吠えるなど）をしても報酬は得られません。犬は試行錯誤を通じて「どの状況でどう行動すれば報酬を得られるか」という**行動ルール（方策）**を学習しています。
- **脳の仕組みと強化学習**:
  脳科学の研究では、動物や人間の脳内において神経伝達物質（ドーパミン）が「予想していた報酬」と「実際に得られた報酬」の差（**報酬予測誤差**）を計算し、良い結果をもたらした行動パターンを脳内で強化（定着）させることが明らかになっています。人工知能の強化学習は、まさにこの生物の「行動・試行錯誤・報酬」による学習メカニズムを数理モデル化したものです。

### 強化学習の成功例：AlphaGo から AlphaZero へ
強化学習が一躍世界的な脚光を浴びた歴史的な契機が、DeepMind社が開発した囲碁AIです。

- **AlphaGo（アルファ碁）**:
  - 2016年に世界トップ棋士に勝利し、世界中に衝撃を与えました。
  - まず約3,000万手におよぶ**人間のプロ棋士の対局データ（棋譜）を教師あり学習**で学んだ後、**強化学習（自分自身との対局＝自己対局）**を何千万回も繰り返すことで、人間の直感を超える新手を編み出し、人類最強の打ち手を超越しました。
- **AlphaZero（アルファゼロ）**:
  - AlphaGoの成功をさらに推し進め、2017年に登場した次世代AIです。
  - 人間の棋譜や定石などの知識を一切使わず、**ゲームの基本ルールだけ**を与えられて学習を開始しました。白紙の状態（ゼロ）から**純粋な強化学習（自己対局の試行錯誤のみ）**だけで打ち方を学び、わずか数十時間の学習でAlphaGoを破る強さに到達しました。さらに、同じ仕組みで将棋やチェスでも世界最強の座を獲得しました。
  - 「人間の過去の知識に頼らずとも、強化学習の試行錯誤だけで人間を超える知能を自律的に獲得できる」ことを示した記念碑的な成果です。

## バージョン管理システム（git）の導入

### バージョン管理システムとは
**バージョン管理システム（VCS: Version Control System）**とは、ファイルの変更履歴（「いつ」「誰が」「どこを」「なぜ」変更したか）を体系的に記録・管理するためのシステムです。

レポート作成やプログラミングを行っていると、過去の状態を残しておこうとして次のようなファイル名を作ってしまった経験はないでしょうか：

- `report.txt`
- `report_v2.txt`
- `report_最終版.txt`
- `report_本当に最終版.txt`
- `report_提出用_修正2.txt`

このような手作業によるファイル管理では、「どれが本当に最新なのか」「過去のバージョンと具体的にどこが違うのか」がすぐに分からなくなってしまいます。また、誤って上書き保存してしまい元の正常な状態に戻せなくなるといった事故も起こりがちです。

バージョン管理システムを導入すると、**ファイル名は1つのままで、過去のあらゆる変更履歴（スナップショット）が安全に保存**されます。いつでも過去の任意の時点の状態に復元したり、変更前後の差分を正確に比較したりできます。現在、世界中のソフトウェア開発で標準として使われている代表的なバージョン管理システムが**Git（ギット）**です。

### バージョン管理システムの仕組み
Gitは、ファイルの変更履歴をゲームの「セーブデータ」のように、特定時点の状態（スナップショット）の連なりとして管理します。

Gitの内部では、主に以下の**3つの領域**を行き来しながら記録を進めます：

1. **作業ツリー（ワークツリー / Working Tree）**:
   実際にファイルを編集したりプログラムを実行したりする、普段の作業フォルダです。
2. **ステージングエリア（インデックス / Staging Area）**:
   次にセーブ（コミット）したい変更を選んで載せる「準備台」です。編集したファイルのうち、今回の記録に含めたい変更だけを `git add` で登録します。
3. **リポジトリ（Repository）**:
   確定した変更履歴が永続的に保存される「記録庫（セーブデータの保管場所）」です。`git commit` を実行すると、ステージングエリアの内容にメッセージ（変更の意図）を添えた新しいセーブポイント（コミット）が作成され、履歴ツリーに記録されます。

- **プッシュ（`push`）とプル（`pull`）**:
  手元で作成したコミット履歴をリモートリポジトリに送信することを「プッシュ（`git push`）」、他のメンバーが更新した最新の履歴を手元に取り込むことを「プル（`git pull`）」と呼びます。
- **ブランチ（Branch / 枝分かれ）**:
  本番のコード（`main` ブランチ）に直接変更を加えるのではなく、新機能の開発やバグ修正ごとに作業の「枝分かれ」を作って作業できます。これにより、複数のメンバーが互いの作業を邪魔することなく同時に並行開発を進められます。
- **プルリクエスト（Pull Request / PR）とコードレビュー**:
  自分のブランチでの開発が完了したら、「本体のコードに合流（マージ）してください」とメンバーに提案するのがプルリクエストです。合流前に他の開発者がコードの内容を確認（レビュー）し、コメントや改善提案をやり取りすることで、バグを未然に防ぎ高い品質を維持します。
- **コンフリクト（競合）の防止と解決**:
  もし複数人が同じファイルの同じ行を同時に変更してしまった場合、Gitは上書きせずに「コンフリクト（競合）」として警告を発します。どちらの変更を採用すべきか人が確認して統合できるため、誰かの作業を誤って消去してしまう事故を防ぎます。

世界中のオープンソースプロジェクト（Python自体や、PyTorch、VS Codeなど）も、このGitHub上で世界各国の開発者が協力しながら日々開発・改善されています。
:::

### なぜAntigravityでの開発にgitが便利なのか？
次回以降の教材では、いよいよcoding agent（Antigravity等）と対話しながら自律エージェントのプログラムを作成していきます。

ここで極めて重要になるのが、このバージョン管理システム「git」の活用です。

1. **変更履歴の自動追跡と安心感**:
   coding agentに「〇〇の機能を追加して」「〇〇のバグを修正して」と指示すると、エージェントは複数のファイルを一度に変更します。gitを使っていれば、エージェントがどの行を書き換えたのかがすべて色付きで明瞭に確認できます。
2. **いつでも元の状態に戻せる（タイムマシン機能）**:
   エージェントの修正によってプログラムが動かなくなってしまったり、方針を変えたくなった場合でも、`git checkout` や `git restore` コマンドで一瞬にして直前の正常な状態に戻すことができます。試行錯誤を恐れずに大胆な開発が行えます。
3. **作業の区切り（コミット）の記録**:
   「環境の作成完了」「学習ループの実装」「グラフ表示機能の追加」といったマイルストーンごとにコミット（記録）を残すことで、開発の進捗が整理されます。

### 基本的なgit操作の流れ
Gitの基本的な操作を、環境のセットアップから日常的な作業の流れに沿って実際に試してみましょう。

#### Gitのインストールと初期設定
まず、パソコンにGitがインストールされているか確認し、初回のみ必要なユーザー情報を設定します。

ターミナル（Windowsの場合はPowerShellまたはGit Bash）を開き、以下のコマンドを実行します：

```bash
git --version
```

- バージョン番号（例: `git version 2.40.0`）が表示されれば、すでにインストールされています。
- **macOS**: コマンドを入力した際に「コマンドライン開発者ツールが必要です」とダイアログが出た場合は、「インストール」を選択して導入します。
- **Windows**: 未インストールの場合は、[Git for Windows（gitforwindows.org）](https://gitforwindows.org/) からインストーラをダウンロードしてセットアップします。

::: {.callout-note}
### Windows環境でのターミナルについて
Git for Windowsを標準設定でインストールすると、環境変数（PATH）が自動的に設定されるため、以後の操作は普段使い慣れている **PowerShell**（またはVS CodeやAntigravity付属の統合ターミナル）のままでそのまま `git` コマンドを実行できます。

なお、インストール時に一緒に導入される **「Git Bash」** を使用しても構いません。Git BashはmacOSと同じUNIX系のコマンド体系（Bash）で動作するため、Macと同じ操作感で進めたい場合はこちらも利用できます。
:::

続いて、コミット（セーブ）時に記録者として残すユーザー名とメールアドレスを設定します（初回のみ）：

```bash
git config --global user.name "Your Name"
git config --global user.email "your_email@example.com"
```

#### 作業フォルダの準備とリポジトリの作成（`git init`）
実習用の作業フォルダを作成し、Gitの管理下に置きます（リポジトリの初期化）。

```bash
# 実習用の作業フォルダを作成して移動
mkdir git_practice
cd git_practice

# Gitリポジトリとして初期化
git init
```

実行すると、フォルダ内に隠しフォルダ `.git/` が生成され、このフォルダ全体がGitの「作業ツリー」として管理されるようになります。

#### ファイルの作成（`.py` と `.md`）
プロジェクトで使うPythonスクリプトと、その内容を説明するMarkdownファイルを作成します。

エディタ等を使って、以下の2つのファイルを作成・保存してください：

- **`hello.py`**（Pythonプログラム）:
  ```python
  # 動作確認用のスクリプト
  print("強化学習エージェントへようこそ！")
  ```

- **`README.md`**（プログラムの説明ファイル）:
  ```markdown
  # 強化学習プロジェクト
  自律エージェントを作成・学習させるためのプロジェクトです。
  ```

ファイルを作成したら、現在のGitの状態を確認してみましょう：

```bash
git status
```

出力結果の `Untracked files`（未追跡のファイル）欄に、赤字などで `hello.py` と `README.md` が表示されます。これは「新しいファイルが作成されたが、まだGitの記録対象（ステージングエリア）に載っていない」状態を示しています。

#### 最初のコミット
作成した2つのファイルをステージングエリア（準備台）に載せ、最初のセーブポイント（コミット）を作成します。

```bash
# 1. 作成したファイルをステージングエリアに追加
git add hello.py README.md
# （フォルダ内の全変更をまとめて追加する場合は git add . でも可能です）

# 2. 状態を確認
git status
```

`Changes to be committed`（コミット予定の変更）として緑色で表示され、セーブの準備が整ったことが分かります。

```bash
# 3. メッセージを添えてコミットを実行
git commit -m "初期作成: hello.pyとREADME.mdを追加"
```

これで、現在の2つのファイルの状態がリポジトリに永久保存されました。
履歴を確認してみましょう：

```bash
git log --oneline
```

コミットのID番号とともに、指定したメッセージが1件表示されます。

#### ファイルの修正
続いて、プログラムに機能を追加し、説明ドキュメントを更新してみましょう。

- **`hello.py`** を次のように書き換えて保存します：
  ```python
  # 動作確認用のスクリプト
  def greet(name):
      print(f"強化学習エージェント {name} へようこそ！")

  greet("Antigravity")
  ```

- **`README.md`** に実行方法の記述を追記して保存します：
  ```markdown
  # 強化学習プロジェクト
  自律エージェントを作成・学習させるためのプロジェクトです。

  ## 実行方法
  `python hello.py` を実行してください。
  ```

ファイルを保存した後、`git status` を実行すると、`modified: hello.py` および `modified: README.md` と表示され、ファイルが変更されたことをGitが自動検知していることが確認できます。

#### 2回目のコミット
変更内容を2つ目のセーブポイントとして記録します。

```bash
# 変更したファイルをステージング
git add .

# 2回目のコミットを実行
git commit -m "挨拶関数を定義し、READMEに実行方法を追記"
```

再度 `git log --oneline` を実行すると、コミット履歴が2件に増え、時系列順に積み重なっていることが確認できます。

#### diffの確認（差分の確認）
Gitの大きな強みは、「過去と現在」や「作業中の修正内容」の差分（どこを書き換えたか）を正確に比較できることです。

1. **コミット間の差分を確認する**:
   直前のコミット（1つ前）と最新のコミットの間でどのような変更が行われたかを確認するには、以下を実行します：
   ```bash
   git diff HEAD~1 HEAD
   ```
   追加された行が緑色（`+`）、削除された行が赤色（`-`）で表示され、変更内容が一目で分かります。
2. **作業中の差分を確認する**:
   ファイルを編集した直後（まだ `git add` や `git commit` をしていない段階）に `git diff` を実行すると、最後のコミットからの変更点を確認できます。coding agentがファイルを修正した直後にこのコマンドを実行すれば、エージェントが「どのファイルのどこを変更したのか」を確実に把握できます。

#### 前の状態に戻す（変更の取り消し・ロールバック）
試行錯誤中に誤ったコードを書いてしまいプログラムが動かなくなったり、ファイルを壊してしまった場合でも、直前のセーブポイントの状態に一瞬で復元できます。

例えば、`hello.py` の中身を適当にいじって壊してみたり、誤って削除してしまったとします。

まだコミットしていない作業ツリーの変更を取り消し、直前のコミット状態に元通り復元するには、以下のコマンドを実行します：

```bash
git restore hello.py
```
（フォルダ全体の変更をまとめて元に戻したい場合は `git restore .`）

エディタで `hello.py` を開き直すと、誤った変更が綺麗に取り消され、直前の正常に動作していた状態に復元されていることが確認できます。

::: {.callout-tip}
### 過去の特定のコミットの状態に戻したい場合
もし「直前」ではなく「2つ前」など過去の特定のコミットの状態を確認したり戻したりしたい場合は、`git restore --source=HEAD~1 hello.py` のように特定のコミットを指定して復元するか、`git checkout コミットID` などを使って過去の時点を閲覧・切り替えることができます。
:::

::: {.callout-note icon=false}
### 練習問題 05-04：変更の取り消し
次の操作を実行してください。

1. `hello.py` の最初の行にデタラメな文字列を入力して保存し、実行するとエラーが出ることを確認してください。
2. 最後のコミットと、現在のファイル内容の差分を表示してください。
3. `hello.py` を最後のコミットの状態に復元し、実行するとエラーが出ずに実行されることを確認してください。
:::

### 練習問題 05-05：コミット
次の操作を実行してください。

1. `hello.py` を修正し、キーボードから名前を入力して「〇〇へようこそ」と表示するようにしてください。
2. `Readme.md` の説明をそれに合わせて修正してください。
3. 変更点をステージング、コミットしてください。
4. コミット履歴を確認してください。
5. 最後のコミットと、その一つ前のコミットの差分を表示してください。
:::
