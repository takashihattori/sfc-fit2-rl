9  GymnasiumとBlackjack環境

9.1 強化学習ライブラリ Gymnasium とは？

第7回・第8回では、「横一列に並んだ3つのマス（状態 A, B, C）」という小さな環境を使って、状態・行動・報酬・方策・価値関数・モンテカルロ法の基礎を学びました。

しかし、トランプゲームや迷路、ロボットの制御、さらにはビデオゲームなど、より本格的で多様な課題に強化学習を適用しようとすると、毎回ゼロから環境のプログラムを作るのは大変です。また、世界中の研究者や開発者が「どの強化学習アルゴリズムが優れているか」を公平に比較するためには、共通のルールと規格で作られた標準的な実験環境（ベンチマーク）が必要になります。

そこで、Pythonで強化学習の実験を行うための世界標準の外部ライブラリとして広く使われているのが Gymnasium（ジムナジウム） です（かつて OpenAI が開発した「OpenAI Gym」の後継ライブラリであり、現在は非営利団体の Farama Foundation によって開発・維持されています）。

9.1.1 Gymnasium の2つの大きな特徴

  1. 多彩な実験環境が最初から揃っている:
    • 本章で扱うトランプゲーム「Blackjack（ブラックジャック）」や、次章以降で扱う棒を倒さないように台車を制御する「Cart Pole（倒立振子）」、月面着陸船を制御する「Lunar Lander」や「Car Racing」など、難易度の異なる多数の実験環境がパッケージ内にあらかじめ用意されています。
  2. すべての環境が「共通のインターフェース（操作手順）」で統一されている:
    • カードゲームであっても物理シミュレーションであっても、エージェントと環境がやり取りするための命令（環境の初期化、行動の実行、結果の受け取りなど）がすべて同じ形式に統一されています。
    • そのため、一度 Gymnasium の使い方を覚えれば、環境の名前を書き換えるだけで、まったく異なるゲームや制御問題に対して同じ強化学習の仕組みをそのまま適用することができます（第10回からの「ミニプロジェクト」では、この Gymnasium の規格に合わせて「自作のゲーム環境」も作成します）。

9.1.2 Gymnasium の基本的な仕組み（環境とのやり取り）

Gymnasium を使ったプログラムでは、どの環境であっても以下の流れで1エピソードを実行します：

  1. 環境の作成（gym.make("環境名")）: 指定した名前の環境オブジェクト（env）を作ります。環境には、どのような状態を取りうるかを表す状態空間（observation_space）と、どのような行動を選べるかを表す行動空間（action_space）が定義されており、env.action_space.sample() を呼ぶだけで「選べる行動の中からランダムに1つ」を簡単に取り出すことができます。
  2. エピソードの開始・初期化（env.reset()）: 新しいエピソードを始めるために環境を初期状態にリセットし、初期状態 state（と補足情報 info）を受け取ります。
  3. 1ステップの実行（env.step(action)）: エージェントが選んだ行動 action を環境に渡して時間を1ステップ進めます。すると環境から次の5つの情報が返ってきます：
env.step(action) の返り値 意味と役割
next_state 行動を実行した結果として遷移した次の状態（\(S_{t+1}\)）。
reward その1ステップの行動によって得られた報酬（\(R_{t+1}\)、数値）。
terminated ゴール到達や勝敗確定、ゲームオーバーなど、本来のルールによってエピソードが終了したかを表す真偽値（True または False）。
truncated 本来の勝敗とは別に、「制限時間（最大ステップ数）に達したため強制的に打ち切られたか」を表す真偽値（True または False）。
info デバッグや分析用の補足情報が入った辞書（通常の学習では使わなくてよい）。

エージェントは、terminated または truncated のいずれかが True になるまで env.step(action) を繰り返し、エピソードが終了したら再び env.reset() で次のエピソードを開始します。

9.2 Blackjack（ブラックジャック）環境

本章では、Gymnasium に収録されている代表的な環境の1つである "Blackjack-v1"（ブラックジャック） を題材として、強化学習エージェントを育てていきます。まずはブラックジャックのゲームルールと、この環境における「状態・行動・報酬」の定義を確認しましょう。

9.2.1 ブラックジャックのゲームルール

ブラックジャックは、プレイヤー（エージェント）とディーラー（親・環境側）が、配られたトランプの「手札の合計点数を、21 を超えない範囲でいかに 21 に近づけるか」を競うカードゲームです。

  1. カードの数え方と「使えるエース（Usable Ace）」:
    • 2 〜 10 のカード：書かれている数字そのままの点数（2点〜10点）。
    • 絵札（J, Q, K）：すべて 10点 として数えます（そのため、山札の中には「10点になるカード（10, J, Q, K）」が他の数字の4倍多く含まれています）。
    • エース（A）：状況に応じて 11点 または 1点 の都合の良い方として数えることができます。
      • 手札にエースがあり、それを 11点として数えても手札の合計が 21 を超えない状態 のことを 「使えるエース（Usable Ace）がある」 と呼びます。
      • たとえば、手札が A と 6 なら、エースを 11点と数えて合計 17点（使えるエースあり） になります。もしこの状態からもう1枚引いて 8 が出たとしても、17 + 8 = 25 で即バーストにはならず、エースを 11点から 1点に数え直すことで合計 1 + 6 + 8 = 15点（使えるエースなし）として生き残ることができます。
  2. プレイヤーの選択（Hit と Stick）:
    • ゲーム開始時、プレイヤーとディーラーに2枚ずつカードが配られます。プレイヤーは自分の2枚のカードすべてを見ることができますが、ディーラーのカードは1枚だけが表向き（見える状態）で、もう1枚は裏向きに伏せられています。
    • プレイヤーは自分のターンで次の2つの行動から1つを選びます：
      • Hit（ヒット）：カードをもう1枚引きます。引いた結果、合計が 21 を超えてしまったら「バースト（Bust）」となり、ディーラーのカードを待つことなくその瞬間にプレイヤーの負けが確定します。21以下であれば、再び Hit か Stick かを選ぶことができます。
      • Stick（スティック／スタンド）：これ以上カードを引かずに現在の合計点数で勝負します。Stick を選ぶとプレイヤーのターンは終了し、ディーラーのターンに移ります。
  3. ディーラーの自動ルールと勝敗判定:
    • プレイヤーが Stick を選ぶと、ディーラーは伏せていたカードを表にし、「手札の合計が 17 以上になるまで機械的にカードを引き続け、17 以上になったら止める」という固定ルールに従ってカードを引きます。
    • ディーラーが 21 を超えてバーストするか、21 以下どうしでプレイヤーの合計点数の方が大きければ プレイヤーの勝ち、同点なら 引き分け、ディーラーの合計点数の方が大きければ プレイヤーの負け となります。

9.2.3 ブラックジャックにおける「状態・行動・報酬」

第7回で学んだ強化学習の3要素（状態・行動・報酬）が、Gymnasium の "Blackjack-v1" 環境ではどのように表現されているかを見てみましょう。

  1. 状態（State）： (プレイヤーの合計点数, ディーラーの表向きカード, 使えるエースの有無) という3つの値からなるタプルで表されます。
    • たとえば (18, 7, False) は、「自分の合計点数が 18 点、ディーラーの表向きカードが 7、11点として使えるエースは False（持っていない）」という状態を表します。
    • 状態の総数は何通りか？： プレイヤーの合計点数が 11点以下 のときは、次にどんなカード（最大でも10点）を引いても絶対に 21 を超えてバーストすることがないため、考えるまでもなく 100% Hit（もう1枚引く）するのが正解です。したがって、エージェントが実質的に「Hit すべきか Stick すべきか」を判断しなければならないのは、次の要素の組み合わせです：
      • プレイヤーの合計点数：12 〜 21 の 10通り
      • ディーラーの表向きカード：1（エース）〜 10 の 10通り
      • 使えるエースの有無：True または False の 2通り を掛け合わせた \(10 \times 10 \times 2 = 200\) 通り の状態になります（初期手札の4〜11点を含めても全体で300通り未満の小さな表に収まります）。
  2. 行動（Action）： 整数 0 または 1 の2択です。
    • 0：Stick（これ以上引かずに手札を確定して勝負する）
    • 1：Hit（カードをもう1枚引く）
  3. 報酬（Reward）と収益 \(G\)：
    • Hit を選んで合計が 21 以下だった場合（まだ自分のターンが続く途中ステップ）の報酬は 0.0 です。
    • エピソードが終了したときにのみ、勝敗に応じて次の報酬が与えられます：
      • プレイヤーの勝ち：+1.0
      • 引き分け：0.0
      • プレイヤーの負け：-1.0
    • ブラックジャックは数ステップで必ず終わる短いゲームであり、途中の報酬がすべて 0.0 で最終的な勝敗そのものを評価したいため、割引率は \(\gamma = 1.0\)（割引なし） とします。このとき、1エピソードで得られる収益 \(G\) は最終的な勝敗報酬（\(+1, 0, -1\)）そのものとなり、行動価値 \(Q(s, a)\) は「状態 \(s\) で行動 \(a\) を選んだときの平均報酬（\(-1.0 \sim +1.0\) の範囲で表される勝ちやすさ）」という非常に直感的な意味を持ちます。
ノートコラム：Python の「タプル（tuple 型）」とは？

Blackjack-v1 の状態 (18, 7, False) や、第7回の Pygame で色や座標を指定した (255, 255, 255)・(x, y) のように、丸括弧 ( ) の中にカンマ , 区切りで複数の値を並べたデータ型を Python では タプル（tuple 型） と呼びます。

第3回で学んだリスト（list 型：[18, 7, False]）とよく似ていますが、次のような共通点と決定的な違いがあります：

  1. リストとの共通点（番号での取り出しと分解代入）:
    • リストと同じく、先頭から 0, 1, 2, ... のインデックス（添字）を使って、state[0]（18）、state[1]（7）、state[2]（False）のように個々の要素を取り出すことができます。
    • また、player, dealer, ace = state のように左辺に複数の変数を並べることで、タプルの中身をそれぞれの変数へ一度に分解して取り出す（アンパック）ことができます。Gymnasium で state, info = env.reset() や next_state, reward, terminated, truncated, info = env.step(action) と書いて複数の返り値を一度に受け取れるのも、実は関数がタプルとして複数の値を返しているからです。
  2. リストとの決定的な違い（後から中身を変更できない）:
    • 角括弧 [ ] で作るリストは、作成したあとも要素を書き換えたり追加・削除したりできます。
    • 一方、丸括弧 ( ) で作るタプルは、一度作成すると後から要素を書き換えたり追加・削除したりすることができない（変更不能／イミュータブル）というルールになっています。
  3. なぜ強化学習の「状態」にタプルが使われるのか？:
    • 最も大きな理由は、「タプルは辞書（dict 型）のキー（見出し）としてそのまま使えるから」です。
    • Python の辞書では、後から中身が変わってしまうリストをキーに指定するとエラーになりますが、中身が決して変わらないタプルはそのまま辞書のキーにすることができます。そのため、Q テーブルを辞書で作る際に Q[(18, 7, False)] のように状態のタプルをそのままキーにして Q 値を記録・検索できるという非常に便利なメリットがあります。

9.3 ランダム方策とディーラー方策で Blackjack をプレイする

import gymnasium as gym

        step += 1

    elif reward < 0:

ランダム方策では勝率が約 28%（平均報酬 \(-0.39\)）、ディーラーと同じ固定ルールでは勝率が約 41%（平均報酬 \(-0.08\)）でした。では、エージェントに「何点のときに引くべきか・止めるべきか」というルールを人間が一切教えず、第8回で学んだモンテカルロ法（Monte Carlo Method）によってゼロから自力で学習させると、ディーラー方策を超えてどこまで強くなれるでしょうか？

9.4.1 Blackjack におけるモンテカルロ法の仕組み

第8回で学んだとおり、モンテカルロ法は「実際にエピソードを最後までプレイし、各状態・行動のペア \((s, a)\) のあとで得られた収益 \(G\) の平均値を記録して行動価値 \(Q(s, a)\) を推定する」という手法です。

ブラックジャックでは、途中の報酬がすべて \(0\) であり割引率も \(\gamma = 1.0\) とするため、1回のエピソードが終わったときに得られた最終報酬（勝ちなら \(+1\)、引き分けなら \(0\)、負けなら \(-1\)）が、そのゲーム中に選んだすべての「状態と行動のペア \((s, a)\)」の収益 \(G\) にそのまま一致します。

この平均値の更新を \(\varepsilon\)-greedy 法（たとえば確率 \(\varepsilon = 0.1\) でランダムに探索し、残りの \(90\%\) で現在 Q 値が高い方の行動を選ぶ）と組み合わせて何十万エピソードも繰り返すと、200通りのすべての状態について「Stick を選んだときの平均報酬 \(Q(s, \text{Stick})\)」と「Hit を選んだときの平均報酬 \(Q(s, \text{Hit})\)」がほぼ正確に求まります。

9.5 Q-learning（Q学習）の考え方

前節ではモンテカルロ法を使ってブラックジャックの最適戦略を学習しました。ここからは、モンテカルロ法と並んで強化学習の最も重要なアルゴリズムである Q-learning（Q学習） の考え方を、数式を使わずに定性的に理解しましょう。

9.5.1 モンテカルロ法の弱点：「ゲームが最後まで終わらないと学べない」

モンテカルロ法は、「実際に1ゲームを最初から最後までプレイし、最終的な勝ち負け（報酬）が確定してから、そのゲームで通ったすべての状態と行動を振り返って評価を更新する」という方法でした。

ブラックジャックのようにわずか2〜3手で勝負がつく短いゲームであれば、この方法でも問題ありません。しかし、もし次のような問題だったらどうなるでしょうか？

  • 迷路のゴールにたどり着くまでに 何百歩・何千歩もかかる問題
  • 将棋や囲碁のように、1局が終わるまでに 100手以上かかる複雑なゲーム
  • ロボットの歩行制御や自動運転のように、明確な「ゲームの終わり（終端）」がないまま動き続ける問題

このような問題では、モンテカルロ法だと「ゴールや終局にたどり着くまで、途中の行動の評価が1ミリも更新されない」という困った事態が起きます。さらに、何百手も動いたあとにようやく結果が出ても、「途中のどの一手が良くて、どの一手が悪かったのか」が最後の結果だけでは分かりにくくなってしまいます。

（日常の勉強に例えるなら、モンテカルロ法は「1年間の勉強がすべて終わって入試の合否が出てから初めて、4月の勉強のやり方が良かったかどうかを振り返る」ようなものです。）

9.5.2 Q-learning の基本アイデア：「1歩進むたびに、移動先の見込みを手掛かりにしてその場で学ぶ」

この弱点を解決したのが Q-learning（Q学習） です。

Q-learning の最大の特徴は、エピソード（ゲーム）が終わるのを待たず、行動を1回実行して次の状態へ「1歩進んだ瞬間」に、その場でただちに行動の評価（Q値）を更新するという点にあります。

では、まだゲームが終わっておらず最終的な勝ち負けも分からない途中で、どうやって「いま選んだ行動が良かったか悪かったか」を判断するのでしょうか？

その秘密は、「1歩進んだ先の状態（次の状態）が持っている『見込みの高さ（その状態で選べる一番良い行動の評価値）』を、手掛かりとして利用する」ことにあります。

9.5.3 具体例でイメージする Q-learning の仕組み

ブラックジャックの具体例で考えてみましょう。

  1. エージェントがすでに何度かプレイして、「手札が 20 点の状態は、そこで Stick を選べばとても勝ちやすい（見込みが非常に高い状態だ）」ということを知っているとします。
  2. ある新しいゲームで、手札が 12 点 の状態から Hit（もう1枚引く）を選んだ結果、8 のカードを引いて 20 点 の状態に進んだとします。
  3. この時点では、まだ自分のターンが続いている（ディーラーと勝負していない）ため、このゲームに最終的に勝つか負けるかは確定していません。
  4. しかし Q-learning では、「12 点で Hit を選んだら、見込みが非常に高い『20 点の状態』に進むことができた！ということは、12 点での Hit の評価もその場で少し引き上げよう！」と判断し、ゲームの終了を待たずに即座に評価を修正します。
  5. そして次のゲーム以降で、「手札 12 点の見込み」が高くなっていれば、今度はさらにその1歩手前（たとえば「手札 7 点で Hit を選んで 12 点に進んだとき」）の評価も引き上げられていきます。

このように、ゴールや勝負所に近い状態の評価から、1歩手前の行動の評価へと「バケツリレー」のように少しずつ価値が伝わっていくのが Q-learning の仕組みです。

9.5.4 Q-learning の3つの重要ポイント

Q-learning が1歩ごとに評価（Q値）を修正するときには、次の3つのルールに従います：

  1. 「いまの評価」を「直後の報酬 ＋ 移動先の最高の見込み」に近づける: 行動を選ぶ前に持っていた「現在の行動の評価」と、実際に1歩動いてみて分かった「そのステップで得られた報酬」に「移動先の状態で選べる一番良い行動の評価（最高の見込み）」を合わせたものを比較します。ただし、もしその1歩でバーストしたり勝負がついたりしてゲームが終了した場合は、その先の状態はないため、単純に「得られた最終報酬（勝ち \(+1\)、引き分け \(0\)、負け \(-1\)）」そのものに評価を近づけます。
  2. 1回で全部書き換えず、「少しずつ（一定の学習率で）」修正する: たまたま1回だけ都合よく 8 を引いて 20 点になれたからといって、「12 点で Hit すれば 100% いつも 20 点になれる！」と思い込んで評価を一気に書き換えてしまうのは危険です（次のゲームでは 10 を引いて 22 点でバーストするかもしれないからです）。 そこで Q-learning では、「現在の評価と、今回の結果から見えた目標とのズレのうち、たとえば 1% や 5% といった一定の割合だけ少しずつ評価を動かす」という方法をとります。この「1回の経験でどれくらいの割合だけ評価を修正するか」を表す数値を 学習率（Learning Rate） と呼びます。何千回・何万回もプレイしながら少しずつ評価を修正し続けることで、カード運のばらつきがならされ、自然な平均値（期待値）へと落ち着いていきます。
  3. 移動先では「最善の行動をとる」と仮定して見積もる: 学習中は \(\varepsilon\)-greedy 法を使っているため、移動先の状態に着いたあと、実際には「探索」によってランダムな行動（たとえば 20 点なのにあえて Hit）を試すこともあります。しかし、1歩前の行動を評価するときには、「移動先の状態では、そこで一番評価が高い最善の行動（20 点なら Stick）を選ぶはずだ」という最高の見込みを基準にして更新します。これにより、探索でいろいろな手を試しながらも、「最善を尽くしたときの正しい行動価値」をぶれずに学習することができます。

9.5.5 モンテカルロ法と Q-learning の比較

ここまで学んだ2つの学習手法の特徴を表に整理しましょう。

比較項目 モンテカルロ法（Monte Carlo Method） Q-learning（Q学習）
評価を更新するタイミング 1エピソード（1ゲーム）が最後まで終了したあとで、通過したすべてのステップをまとめて更新する。 行動を1回選んで1歩進むたびに、ゲーム終了を待たずその場で即座に更新する。
何を基準（手掛かり）にして更新するか ゲーム終了時に確定した「実際の最終結果（収益）」の平均をとる。 その1歩で得られた「直後の報酬」と「移動先の状態での最高の見込み（最大Q値）」を手掛かりにする（バケツリレー方式）。
長いエピソードや終わりのない問題 最後まで終わらないと学べないため、ステップ数が長い問題や終わりのない問題には不向き。 1歩ごとにリアルタイムで学べるため、迷路や制御などステップ数が長い問題にも非常に強い。

## 強化学習ライブラリ Gymnasium とは？

第7回・第8回では、「横一列に並んだ3つのマス（状態 A, B, C）」という小さな環境を使って、状態・行動・報酬・方策・価値関数・モンテカルロ法の基礎を学びました。

しかし、トランプゲームや迷路、ロボットの制御、さらにはビデオゲームなど、より本格的で多様な課題に強化学習を適用しようとすると、毎回ゼロから環境のプログラムを作るのは大変です。また、世界中の研究者や開発者が「どの強化学習アルゴリズムが優れているか」を公平に比較するためには、**共通のルールと規格で作られた標準的な実験環境（ベンチマーク）**が必要になります。

そこで、Pythonで強化学習の実験を行うための世界標準の外部ライブラリとして広く使われているのが **Gymnasium（ジムナジウム）** です（かつて OpenAI が開発した「OpenAI Gym」の後継ライブラリであり、現在は非営利団体の Farama Foundation によって開発・維持されています）。

### Gymnasium の基本的な仕組み（環境とのやり取り）

Gymnasium を使ったプログラムでは、どの環境であっても以下の流れで1エピソードを実行します：

1. **環境の作成（`gym.make("環境名")`）**:
   指定した名前の環境オブジェクト（`env`）を作ります。環境には、どのような状態を取りうるかを表す**状態空間（`observation_space`）**と、どのような行動を選べるかを表す**行動空間（`action_space`）**が定義されており、`env.action_space.sample()` を呼ぶだけで「選べる行動の中からランダムに1つ」を簡単に取り出すことができます。
2. **エピソードの開始・初期化（`env.reset()`）**:
   新しいエピソードを始めるために環境を初期状態にリセットし、**初期状態 `state`**（と補足情報 `info`）を受け取ります。
3. **1ステップの実行（`env.step(action)`）**:
   エージェントが選んだ行動 `action` を環境に渡して時間を1ステップ進めます。すると環境から次の**5つの情報**が返ってきます：

| `env.step(action)` の返り値 | 意味と役割 |
| :--- | :--- |
| **`next_state`** | 行動を実行した結果として遷移した**次の状態**（$S_{t+1}$）。 |
| **`reward`** | その1ステップの行動によって得られた**報酬**（$R_{t+1}$、数値）。 |
| **`terminated`** | ゴール到達や勝敗確定、ゲームオーバーなど、**本来のルールによってエピソードが終了したか**を表す真偽値（`True` または `False`）。 |
| **`truncated`** | 本来の勝敗とは別に、「制限時間（最大ステップ数）に達したため強制的に打ち切られたか」を表す真偽値（`True` または `False`）。 |
| **`info`** | デバッグや分析用の補足情報が入った辞書（通常の学習では使わなくてよい）。 |

エージェントは、`terminated` または `truncated` のいずれかが `True` になるまで `env.step(action)` を繰り返し、エピソードが終了したら再び `env.reset()` で次のエピソードを開始します。

1. **カードの数え方と「使えるエース（Usable Ace）」**:
   - **`2` 〜 `10` のカード**：書かれている数字そのままの点数（2点〜10点）。
   - **絵札（`J`, `Q`, `K`）**：すべて **10点** として数えます（そのため、山札の中には「10点になるカード（10, J, Q, K）」が他の数字の4倍多く含まれています）。
   - **エース（`A`）**：状況に応じて **11点** または **1点** の都合の良い方として数えることができます。
     - 手札にエースがあり、それを **11点として数えても手札の合計が 21 を超えない状態** のことを **「使えるエース（Usable Ace）がある」** と呼びます。
     - たとえば、手札が `A` と `6` なら、エースを 11点と数えて合計 **17点（使えるエースあり）** になります。もしこの状態からもう1枚引いて `8` が出たとしても、17 + 8 = 25 で即バーストにはならず、**エースを 11点から 1点に数え直すことで合計 1 + 6 + 8 = 15点（使えるエースなし）として生き残る**ことができます。

2. **プレイヤーの選択（`Hit` と `Stick`）**:
   - ゲーム開始時、プレイヤーとディーラーに2枚ずつカードが配られます。プレイヤーは自分の2枚のカードすべてを見ることができますが、**ディーラーのカードは1枚だけが表向き（見える状態）**で、もう1枚は裏向きに伏せられています。
   - プレイヤーは自分のターンで次の2つの行動から1つを選びます：
     - **`Hit`（ヒット）**：カードをもう1枚引きます。引いた結果、合計が **21 を超えてしまったら「バースト（Bust）」となり、ディーラーのカードを待つことなくその瞬間にプレイヤーの負けが確定**します。21以下であれば、再び `Hit` か `Stick` かを選ぶことができます。
     - **`Stick`（スティック／スタンド）**：これ以上カードを引かずに現在の合計点数で勝負します。`Stick` を選ぶとプレイヤーのターンは終了し、ディーラーのターンに移ります。

3. **ディーラーの自動ルールと勝敗判定**:
   - プレイヤーが `Stick` を選ぶと、ディーラーは伏せていたカードを表にし、**「手札の合計が 17 以上になるまで機械的にカードを引き続け、17 以上になったら止める」**という固定ルールに従ってカードを引きます。
   - ディーラーが 21 を超えてバーストするか、21 以下どうしでプレイヤーの合計点数の方が大きければ **プレイヤーの勝ち**、同点なら **引き分け**、ディーラーの合計点数の方が大きければ **プレイヤーの負け** となります。

(function() {
  const SUITS = [
    { symbol: "♠", color: "black" },
    { symbol: "♥", color: "red" },
    { symbol: "♦", color: "red" },
    { symbol: "♣", color: "black" }
  ];
  const RANKS = [
    { label: "A", value: 1 },
    { label: "2", value: 2 },
    { label: "3", value: 3 },
    { label: "4", value: 4 },
    { label: "5", value: 5 },
    { label: "6", value: 6 },
    { label: "7", value: 7 },
    { label: "8", value: 8 },
    { label: "9", value: 9 },
    { label: "10", value: 10 },
    { label: "J", value: 10 },
    { label: "Q", value: 10 },
    { label: "K", value: 10 }
  ];

  let playerHand = [];
  let dealerHand = [];
  let isGameOver = false;

  let gamesCount = 0;
  let wins = 0;
  let draws = 0;
  let losses = 0;
  let totalReward = 0;

  function drawCard() {
    const suit = SUITS[Math.floor(Math.random() * SUITS.length)];
    const rank = RANKS[Math.floor(Math.random() * RANKS.length)];
    return {
      suit: suit.symbol,
      color: suit.color,
      label: rank.label,
      value: rank.value
    };
  }

  function evaluateHand(hand) {
    let sum = 0;
    let hasAce = false;
    for (const c of hand) {
      sum += c.value;
      if (c.value === 1) hasAce = true;
    }
    let usableAce = false;
    if (hasAce && sum + 10 <= 21) {
      sum += 10;
      usableAce = true;
    }
    return { sum, usableAce };
  }

  function renderCard(card, hidden) {
    const div = document.createElement("div");
    if (hidden) {
      div.className = "bj-card bj-card-hidden";
      div.textContent = "？";
      return div;
    }
    div.className = `bj-card bj-card-${card.color}`;
    const suitEl = document.createElement("div");
    suitEl.className = "bj-card-suit";
    suitEl.textContent = card.suit;

    const rankEl = document.createElement("div");
    rankEl.className = "bj-card-rank";
    rankEl.textContent = card.label;

    const ptEl = document.createElement("div");
    ptEl.className = "bj-card-point";
    ptEl.textContent = card.value === 1 ? "1/11点" : `${card.value}点`;

    div.appendChild(suitEl);
    div.appendChild(rankEl);
    div.appendChild(ptEl);
    return div;
  }

  function updateBoard() {
    const dealerCardsEl = document.getElementById("bj-dealer-cards");
    const playerCardsEl = document.getElementById("bj-player-cards");
    const dealerScoreEl = document.getElementById("bj-dealer-score");
    const playerScoreEl = document.getElementById("bj-player-score");
    const usableAceEl = document.getElementById("bj-usable-ace-badge");

    if (!dealerCardsEl || !playerCardsEl) return;

    dealerCardsEl.innerHTML = "";
    dealerHand.forEach((card, idx) => {
      const hide = !isGameOver && idx === 1;
      dealerCardsEl.appendChild(renderCard(card, hide));
    });

    playerCardsEl.innerHTML = "";
    playerHand.forEach((card) => {
      playerCardsEl.appendChild(renderCard(card, false));
    });

    const pEval = evaluateHand(playerHand);
    playerScoreEl.textContent = `合計: ${pEval.sum} 点${pEval.sum > 21 ? "（バースト！）" : ""}`;

    if (pEval.usableAce) {
      usableAceEl.textContent = "使えるエース: あり（Aを11点として計算中）";
      usableAceEl.className = "bj-ace-badge bj-ace-active";
    } else {
      usableAceEl.textContent = "使えるエース: なし";
      usableAceEl.className = "bj-ace-badge";
    }

    if (!isGameOver) {
      const upCard = dealerHand[0];
      const upText = upCard.value === 1 ? "A（1または11点）" : `${upCard.value} 点`;
      dealerScoreEl.textContent = `表カード: ${upText}（もう1枚は伏せ札）`;
    } else {
      const dEval = evaluateHand(dealerHand);
      dealerScoreEl.textContent = `合計: ${dEval.sum} 点${dEval.sum > 21 ? "（バースト！）" : ""}`;
    }

    document.getElementById("bj-hit-btn").disabled = isGameOver;
    document.getElementById("bj-stick-btn").disabled = isGameOver;
    document.getElementById("bj-next-btn").disabled = !isGameOver;
  }

  function updateStatsUI() {
    document.getElementById("bj-games-count").textContent = gamesCount;
    document.getElementById("bj-wins").textContent = wins;
    document.getElementById("bj-draws").textContent = draws;
    document.getElementById("bj-losses").textContent = losses;

    const winrateEl = document.getElementById("bj-winrate");
    const avgRewardEl = document.getElementById("bj-avg-reward");
    const totalRewardEl = document.getElementById("bj-total-reward");

    if (gamesCount > 0) {
      const rate = ((wins / gamesCount) * 100).toFixed(0);
      winrateEl.textContent = `（勝率 ${rate}%）`;
      const avg = (totalReward / gamesCount).toFixed(2);
      avgRewardEl.textContent = (totalReward > 0 ? "+" : "") + avg;
      const sign = totalReward > 0 ? "+" : "";
      totalRewardEl.textContent = `（計 ${sign}${totalReward}）`;
    } else {
      winrateEl.textContent = "（勝率 -）";
      avgRewardEl.textContent = "0.00";
      totalRewardEl.textContent = "（計 0）";
    }
  }

  function setMessage(text, type) {
    const msgEl = document.getElementById("bj-message");
    if (!msgEl) return;
    msgEl.innerHTML = text;
    if (type === "win") {
      msgEl.style.background = "#dcfce7";
      msgEl.style.borderColor = "#86efac";
      msgEl.style.color = "#14532d";
    } else if (type === "lose") {
      msgEl.style.background = "#fee2e2";
      msgEl.style.borderColor = "#fca5a5";
      msgEl.style.color = "#7f1d1d";
    } else if (type === "draw") {
      msgEl.style.background = "#f1f5f9";
      msgEl.style.borderColor = "#cbd5e1";
      msgEl.style.color = "#334155";
    } else {
      msgEl.style.background = "#eff6ff";
      msgEl.style.borderColor = "#bfdbfe";
      msgEl.style.color = "#1e40af";
    }
  }

  function finishGame(outcome, reasonText) {
    isGameOver = true;
    gamesCount++;
    if (outcome === "win") {
      wins++;
      totalReward += 1;
      setMessage(`🎉 <strong>あなたの勝ち！（報酬 +1.0）</strong> ${reasonText}`, "win");
    } else if (outcome === "lose") {
      losses++;
      totalReward -= 1;
      setMessage(`💥 <strong>あなたの負け…（報酬 -1.0）</strong> ${reasonText}`, "lose");
    } else {
      draws++;
      setMessage(`🤝 <strong>引き分け（報酬 0.0）</strong> ${reasonText}`, "draw");
    }
    updateBoard();
    updateStatsUI();
  }

  function onHit() {
    if (isGameOver) return;
    playerHand.push(drawCard());
    const pEval = evaluateHand(playerHand);
    if (pEval.sum > 21) {
      finishGame(
        "lose",
        `あなたの合計が ${pEval.sum} 点となり、21 を超えてバーストしました。`
      );
    } else {
      setMessage(
        `カードを1枚引いて合計 <strong>${pEval.sum} 点</strong> になりました。続けて「Hit」か「Stick」を選んでください。`,
        "info"
      );
      updateBoard();
    }
  }

  function onStick() {
    if (isGameOver) return;
    while (evaluateHand(dealerHand).sum < 17) {
      dealerHand.push(drawCard());
    }
    const pSum = evaluateHand(playerHand).sum;
    const dSum = evaluateHand(dealerHand).sum;

    if (dSum > 21) {
      finishGame(
        "win",
        `ディーラーが合計 ${dSum} 点でバーストしました！（あなた: ${pSum} 点）`
      );
    } else if (pSum > dSum) {
      finishGame(
        "win",
        `あなた ${pSum} 点 vs ディーラー ${dSum} 点で上回りました！`
      );
    } else if (pSum < dSum) {
      finishGame(
        "lose",
        `あなた ${pSum} 点 vs ディーラー ${dSum} 点で及びませんでした。`
      );
    } else {
      finishGame(
        "draw",
        `あなた ${pSum} 点 vs ディーラー ${dSum} 点で同点でした。`
      );
    }
  }

  function startNewHand() {
    playerHand = [drawCard(), drawCard()];
    dealerHand = [drawCard(), drawCard()];
    isGameOver = false;
    const pEval = evaluateHand(playerHand);
    setMessage(
      `新しいカードが配られました（あなたの合計: <strong>${pEval.sum} 点</strong>）。「Hit」か「Stick」を選んでください。`,
      "info"
    );
    updateBoard();
  }

  function resetStats() {
    gamesCount = 0;
    wins = 0;
    draws = 0;
    losses = 0;
    totalReward = 0;
    updateStatsUI();
    startNewHand();
  }

  function initBlackjack() {
    const hitBtn = document.getElementById("bj-hit-btn");
    const stickBtn = document.getElementById("bj-stick-btn");
    const nextBtn = document.getElementById("bj-next-btn");
    const resetBtn = document.getElementById("bj-reset-stats-btn");
    if (!hitBtn) return;

    hitBtn.addEventListener("click", onHit);
    stickBtn.addEventListener("click", onStick);
    nextBtn.addEventListener("click", startNewHand);
    resetBtn.addEventListener("click", resetStats);

    startNewHand();
  }

  if (document.readyState === "loading") {
    document.addEventListener("DOMContentLoaded", initBlackjack);
  } else {
    initBlackjack();
  }
})();
</script>

1. **状態（State）**：
   `(プレイヤーの合計点数, ディーラーの表向きカード, 使えるエースの有無)` という3つの値からなるタプルで表されます。
   - たとえば `(18, 7, False)` は、「自分の合計点数が `18` 点、ディーラーの表向きカードが `7`、11点として使えるエースは `False`（持っていない）」という状態を表します。
   - **状態の総数は何通りか？**：
     プレイヤーの合計点数が **11点以下** のときは、次にどんなカード（最大でも10点）を引いても絶対に 21 を超えてバーストすることがないため、考えるまでもなく 100% `Hit`（もう1枚引く）するのが正解です。したがって、エージェントが実質的に「`Hit` すべきか `Stick` すべきか」を判断しなければならないのは、次の要素の組み合わせです：
     - プレイヤーの合計点数：**`12` 〜 `21` の 10通り**
     - ディーラーの表向きカード：**`1`（エース）〜 `10` の 10通り**
     - 使えるエースの有無：**`True` または `False` の 2通り**
     を掛け合わせた **$10 \times 10 \times 2 = 200$ 通り** の状態になります（初期手札の4〜11点を含めても全体で300通り未満の小さな表に収まります）。

2. **行動（Action）**：
   整数 `0` または `1` の2択です。
   - **`0`：`Stick`**（これ以上引かずに手札を確定して勝負する）
   - **`1`：`Hit`**（カードをもう1枚引く）

3. **報酬（Reward）と収益 $G$**：
   - `Hit` を選んで合計が 21 以下だった場合（まだ自分のターンが続く途中ステップ）の報酬は **`0.0`** です。
   - エピソードが終了したときにのみ、勝敗に応じて次の報酬が与えられます：
     - **プレイヤーの勝ち：`+1.0`**
     - **引き分け：`0.0`**
     - **プレイヤーの負け：`-1.0`**
   - ブラックジャックは数ステップで必ず終わる短いゲームであり、途中の報酬がすべて `0.0` で最終的な勝敗そのものを評価したいため、割引率は **$\gamma = 1.0$（割引なし）** とします。このとき、**1エピソードで得られる収益 $G$ は最終的な勝敗報酬（$+1, 0, -1$）そのもの**となり、**行動価値 $Q(s, a)$ は「状態 $s$ で行動 $a$ を選んだときの平均報酬（$-1.0 \sim +1.0$ の範囲で表される勝ちやすさ）」**という非常に直感的な意味を持ちます。

### コラム：Python の「タプル（`tuple` 型）」とは？

`Blackjack-v1` の状態 `(18, 7, False)` や、第7回の Pygame で色や座標を指定した `(255, 255, 255)`・`(x, y)` のように、**丸括弧 `( )` の中にカンマ `,` 区切りで複数の値を並べたデータ型**を Python では **タプル（`tuple` 型）** と呼びます。

第3回で学んだ**リスト（`list` 型：`[18, 7, False]`）**とよく似ていますが、次のような共通点と決定的な違いがあります：

1. **リストとの共通点（番号での取り出しと分解代入）**:
   - リストと同じく、先頭から `0, 1, 2, ...` のインデックス（添字）を使って、`state[0]`（`18`）、`state[1]`（`7`）、`state[2]`（`False`）のように個々の要素を取り出すことができます。
   - また、`player, dealer, ace = state` のように左辺に複数の変数を並べることで、タプルの中身をそれぞれの変数へ一度に分解して取り出す（**アンパック**）ことができます。Gymnasium で `state, info = env.reset()` や `next_state, reward, terminated, truncated, info = env.step(action)` と書いて複数の返り値を一度に受け取れるのも、実は関数がタプルとして複数の値を返しているからです。
2. **リストとの決定的な違い（後から中身を変更できない）**:
   - 角括弧 `[ ]` で作る**リスト**は、作成したあとも要素を書き換えたり追加・削除したりできます。
   - 一方、丸括弧 `( )` で作る**タプル**は、**一度作成すると後から要素を書き換えたり追加・削除したりすることができない（変更不能／イミュータブル）**というルールになっています。
3. **なぜ強化学習の「状態」にタプルが使われるのか？**:
   - 最も大きな理由は、**「タプルは辞書（`dict` 型）のキー（見出し）としてそのまま使えるから」**です。
   - Python の辞書では、後から中身が変わってしまうリストをキーに指定するとエラーになりますが、中身が決して変わらないタプルはそのまま辞書のキーにすることができます。そのため、Q テーブルを辞書で作る際に `Q[(18, 7, False)]` のように**状態のタプルをそのままキーにして Q 値を記録・検索できる**という非常に便利なメリットがあります。
:::

### ランダム方策で 5 エピソード実行するプログラム

以下のソースコードをコピーし、`blackjack_play.py` というファイル名で保存して実行してみましょう。

```python
import gymnasium as gym

# 1. Blackjack環境の作成
env = gym.make("Blackjack-v1")

print("=== ランダム方策による 5 エピソードのプレイ履歴 ===")

# 2. 5エピソード（5ゲーム）を実行する
for episode in range(1, 6):
    # 環境をリセットして初期状態 (プレイヤー合計, ディーラー表カード, 使えるエース) を受け取る
    state, info = env.reset()
    terminated = False
    truncated = False
    step = 1

    print(f"\n[エピソード {episode}]")

    # エピソードが終了するまで繰り返す
    while not (terminated or truncated):
        # ランダム方策：Stick (0) と Hit (1) を 50% ずつランダムに選ぶ
        action = env.action_space.sample()
        action_name = "Hit (1)" if action == 1 else "Stick (0)"

        # 選んだ行動を環境に渡して1ステップ進める
        next_state, reward, terminated, truncated, info = env.step(action)

        print(f"  ステップ {step}: 状態 {state} -> 行動: {action_name} -> 次の状態 {next_state}")

        state = next_state
        step += 1

    # 最終報酬から勝敗結果を表示する
    if reward > 0:
        result = "勝ち"
    elif reward < 0:
        result = "負け"
    else:
        result = "引き分け"
    print(f"  結果: {result} | 報酬: {reward:+.1f}")

env.close()
```

### 作成するプログラムの仕様

Antigravity には、モンテカルロ法で学習を行い、その結果獲得された「ブラックジャックの戦略表（ヒートマップ）」と「学習曲線」を可視化するプログラム `blackjack_mc.py` を作成してもらいます：

1. **モンテカルロ法による学習（500,000 エピソード）**:
   - `"Blackjack-v1"` 環境において、$\varepsilon$-greedy 法（$\varepsilon = 0.1$）に従いながら **50万エピソード（500,000回）** プレイして行動価値 $Q(s, a)$（各状態で得られた最終報酬の平均値）を学習する。
   - 学習の進み具合を確認できるよう、一定間隔（例：10,000エピソードごと）の平均報酬を記録しておく。
2. **学習済みエージェントのテスト（10,000 エピソード）**:
   - 50万エピソードの学習が完了したあと、探索をオフにして**「各状態で常に $Q(s, \text{Stick})$ と $Q(s, \text{Hit})$ のうち値が高い方の行動を選ぶ（$\varepsilon = 0$）」**テストを 10,000 エピソード実行し、勝率・引き分け率・敗北率・平均報酬を表示してランダム方策と比較できるようにする。
3. **獲得した戦略表（ヒートマップ）と学習曲線のグラフ描画（Matplotlib）**:
   - 縦軸を「プレイヤーの合計点数（12〜21）」、横軸を「ディーラーの表向きカード（1〜10）」としたマス目を作り、各マスで **`Stick (0)` と `Hit (1)` のどちらの Q 値が高くなったか（推奨行動）** を色分けして表示する2枚の表（**「使えるエースなし（`False`）」**と**「使えるエースあり（`True`）」**）を描画する。
   - あわせて、学習エピソード数の経過に伴う平均報酬の推移（学習曲線）もプロットする。

### コラム：なぜ最適方策でも平均報酬がマイナス（約 $-0.05$）なのか？
「50万回も学習したのに、なぜ平均報酬がプラスにならないのだろう？」と疑問に思ったかもしれません。
実は、カジノのブラックジャックのルールでは**「プレイヤーが先にカードを引き、もしプレイヤーとディーラーの両方が21を超えてバーストするような展開でも、先にバーストしたプレイヤーの負け（$-1$）になる」**という非対称なルールになっています。この「先攻バースト即負け」のハンディキャップがあるため、数学的に可能な最善の戦略（最適方策）でプレイしても、プレイヤーの期待勝率は約 42〜43%、引き分けが約 8〜9%、負けが約 48〜49% となり、**理論上の最高平均報酬は約 $-0.04 \sim -0.05$** であることが知られています（このわずかな差がカジノ側の利益＝ハウスエッジになります）。つまり、平均報酬が $-0.05$ 前後に達したということは、**エージェントが理論上のほぼ完璧な最適方策を獲得できた証拠**なのです！
:::

## Q-learning（Q学習）の考え方

前節ではモンテカルロ法を使ってブラックジャックの最適戦略を学習しました。ここからは、モンテカルロ法と並んで強化学習の最も重要なアルゴリズムである **Q-learning（Q学習）** の考え方を、数式を使わずに定性的に理解しましょう。

### モンテカルロ法の弱点：「ゲームが最後まで終わらないと学べない」

モンテカルロ法は、「実際に1ゲームを最初から最後までプレイし、最終的な勝ち負け（報酬）が確定してから、そのゲームで通ったすべての状態と行動を振り返って評価を更新する」という方法でした。

ブラックジャックのようにわずか2〜3手で勝負がつく短いゲームであれば、この方法でも問題ありません。しかし、もし次のような問題だったらどうなるでしょうか？

- 迷路のゴールにたどり着くまでに **何百歩・何千歩もかかる問題**
- 将棋や囲碁のように、1局が終わるまでに **100手以上かかる複雑なゲーム**
- ロボットの歩行制御や自動運転のように、**明確な「ゲームの終わり（終端）」がないまま動き続ける問題**

このような問題では、モンテカルロ法だと「ゴールや終局にたどり着くまで、途中の行動の評価が1ミリも更新されない」という困った事態が起きます。さらに、何百手も動いたあとにようやく結果が出ても、「途中のどの一手が良くて、どの一手が悪かったのか」が最後の結果だけでは分かりにくくなってしまいます。

（日常の勉強に例えるなら、モンテカルロ法は**「1年間の勉強がすべて終わって入試の合否が出てから初めて、4月の勉強のやり方が良かったかどうかを振り返る」**ようなものです。）

### Q-learning の基本アイデア：「1歩進むたびに、移動先の見込みを手掛かりにしてその場で学ぶ」

この弱点を解決したのが **Q-learning（Q学習）** です。

Q-learning の最大の特徴は、**エピソード（ゲーム）が終わるのを待たず、行動を1回実行して次の状態へ「1歩進んだ瞬間」に、その場でただちに行動の評価（Q値）を更新する**という点にあります。

では、まだゲームが終わっておらず最終的な勝ち負けも分からない途中で、どうやって「いま選んだ行動が良かったか悪かったか」を判断するのでしょうか？

その秘密は、**「1歩進んだ先の状態（次の状態）が持っている『見込みの高さ（その状態で選べる一番良い行動の評価値）』を、手掛かりとして利用する」**ことにあります。

### 具体例でイメージする Q-learning の仕組み

ブラックジャックの具体例で考えてみましょう。

1. エージェントがすでに何度かプレイして、**「手札が 20 点の状態は、そこで `Stick` を選べばとても勝ちやすい（見込みが非常に高い状態だ）」**ということを知っているとします。
2. ある新しいゲームで、手札が **12 点** の状態から `Hit`（もう1枚引く）を選んだ結果、`8` のカードを引いて **20 点** の状態に進んだとします。
3. この時点では、まだ自分のターンが続いている（ディーラーと勝負していない）ため、このゲームに最終的に勝つか負けるかは確定していません。
4. しかし Q-learning では、**「12 点で `Hit` を選んだら、見込みが非常に高い『20 点の状態』に進むことができた！ということは、12 点での `Hit` の評価もその場で少し引き上げよう！」**と判断し、ゲームの終了を待たずに即座に評価を修正します。
5. そして次のゲーム以降で、「手札 12 点の見込み」が高くなっていれば、今度はさらにその1歩手前（たとえば「手札 7 点で `Hit` を選んで 12 点に進んだとき」）の評価も引き上げられていきます。

このように、**ゴールや勝負所に近い状態の評価から、1歩手前の行動の評価へと「バケツリレー」のように少しずつ価値が伝わっていく**のが Q-learning の仕組みです。

### Q-learning の3つの重要ポイント

Q-learning が1歩ごとに評価（Q値）を修正するときには、次の3つのルールに従います：

1. **「いまの評価」を「直後の報酬 ＋ 移動先の最高の見込み」に近づける**:
   行動を選ぶ前に持っていた「現在の行動の評価」と、実際に1歩動いてみて分かった「そのステップで得られた報酬」に「移動先の状態で選べる一番良い行動の評価（最高の見込み）」を合わせたものを比較します。ただし、もしその1歩でバーストしたり勝負がついたりして**ゲームが終了した場合**は、その先の状態はないため、単純に**「得られた最終報酬（勝ち $+1$、引き分け $0$、負け $-1$）」**そのものに評価を近づけます。
2. **1回で全部書き換えず、「少しずつ（一定の学習率で）」修正する**:
   たまたま1回だけ都合よく `8` を引いて 20 点になれたからといって、「12 点で `Hit` すれば 100% いつも 20 点になれる！」と思い込んで評価を一気に書き換えてしまうのは危険です（次のゲームでは `10` を引いて 22 点でバーストするかもしれないからです）。
   そこで Q-learning では、**「現在の評価と、今回の結果から見えた目標とのズレのうち、たとえば 1% や 5% といった一定の割合だけ少しずつ評価を動かす」**という方法をとります。この「1回の経験でどれくらいの割合だけ評価を修正するか」を表す数値を **学習率（Learning Rate）** と呼びます。何千回・何万回もプレイしながら少しずつ評価を修正し続けることで、カード運のばらつきがならされ、自然な平均値（期待値）へと落ち着いていきます。
3. **移動先では「最善の行動をとる」と仮定して見積もる**:
   学習中は $\varepsilon$-greedy 法を使っているため、移動先の状態に着いたあと、実際には「探索」によってランダムな行動（たとえば 20 点なのにあえて `Hit`）を試すこともあります。しかし、1歩前の行動を評価するときには、**「移動先の状態では、そこで一番評価が高い最善の行動（20 点なら `Stick`）を選ぶはずだ」という最高の見込み**を基準にして更新します。これにより、探索でいろいろな手を試しながらも、「最善を尽くしたときの正しい行動価値」をぶれずに学習することができます。

### モンテカルロ法と Q-learning の比較

ここまで学んだ2つの学習手法の特徴を表に整理しましょう。

| 比較項目 | モンテカルロ法（Monte Carlo Method） | Q-learning（Q学習） |
| :--- | :--- | :--- |
| **評価を更新するタイミング** | **1エピソード（1ゲーム）が最後まで終了したあと**で、通過したすべてのステップをまとめて更新する。 | **行動を1回選んで1歩進むたび**に、ゲーム終了を待たずその場で即座に更新する。 |
| **何を基準（手掛かり）にして更新するか** | ゲーム終了時に確定した**「実際の最終結果（収益）」**の平均をとる。 | その1歩で得られた**「直後の報酬」と「移動先の状態での最高の見込み（最大Q値）」**を手掛かりにする（バケツリレー方式）。 |
| **長いエピソードや終わりのない問題** | 最後まで終わらないと学べないため、ステップ数が長い問題や終わりのない問題には**不向き**。 | 1歩ごとにリアルタイムで学べるため、迷路や制御などステップ数が長い問題にも**非常に強い**。 |

本章で扱った4つの方策・学習手法の成績を一覧表で比べてみましょう。

| エージェントの方策・手法 | 勝率（目安） | 引き分け率 | 敗北率 | 平均報酬 | 行動の特徴 |
| :--- | :---: | :---: | :---: | :---: | :--- |
| **① ランダム方策** | 約 $28\%$ | 約 $4\%$ | 約 $68\%$ | **約 $-0.39$** | 20点でも50%で引いて自滅するなど無謀な選択が多い |
| **② ディーラーと同じ方策** | 約 $41\%$ | 約 $10\%$ | 約 $49\%$ | **約 $-0.08$** | 自分の合計点数（17以上か）だけを見て固定ルールで判断 |
| **③ モンテカルロ法** | **約 $43\%$** | 約 $9\%$ | **約 $48\%$** | **約 $-0.05$** | ゲーム終了後の結果の平均から基本戦略を自律獲得 |
| **④ Q-learning** | **約 $43\%$** | 約 $9\%$ | **約 $48\%$** | **約 $-0.05$** | 1歩ごとの移動先の見込みから基本戦略を自律獲得 |

ブラックジャックのように数手で勝負がつく環境では、モンテカルロ法と Q-learning はどちらも同じ理論上の限界値（平均報酬約 $-0.05$）まで到達します。そして次章（第10回）で扱う「倒立振子（Cart Pole）」やミニプロジェクトで作成する自作ゲームのように、**1エピソードで何十ステップ・何百ステップも行動を続ける環境では、1歩ごとにリアルタイムで学べる Q-learning（さらにはそれを発展させた深層強化学習）がさらなる真価を発揮する**ことになります。

## まとめ

- **強化学習ライブラリ Gymnasium**: 多彩な標準実験環境を備え、`gym.make("環境名")` による環境作成、`env.reset()` による初期化、`env.step(action)` による1ステップ実行（次の状態・報酬・終了フラグ `terminated`・打ち切りフラグ `truncated`・補足情報の返却）という**共通のインターフェース**で統一された Python の世界標準ライブラリ。
- **Blackjack（`"Blackjack-v1"`）環境**: 手札の合計を 21 を超えない範囲で 21 に近づけるカードゲーム。状態は **`(プレイヤーの合計点数, ディーラーの表向きカード, 使えるエースの有無)`** の3要素タプル、行動は **`Stick (0)`** と **`Hit (1)`** の2択、最終報酬は **勝ち $+1.0$・引き分け $0.0$・負け $-1.0$** で定義される。
- **ランダム方策とモンテカルロ法の比較**: 毎回ランダムに行動を選ぶ方策ではバーストによる自滅などで勝率約 28%（平均報酬約 $-0.39$）にとどまるのに対し、ゲーム終了時の報酬の平均から行動価値 $Q(s, a)$ を学ぶ**モンテカルロ法**（＋ $\varepsilon$-greedy 法）を用いると、カードのルールを教えなくても「17以上は止める」「12〜16はディーラーの表カード次第で使い分ける」「使えるエースがあれば積極的に引く」といった基本戦略を自力で獲得し、勝率約 43%（理論上限の平均報酬約 $-0.05$）に達する。
- **Q-learning（Q学習）の定性的な仕組み**: エピソードが最後まで終わるのを待たず、**1歩進むたびに「その場で得られた報酬」と「移動先の状態が持つ最高の見込み（最良行動の評価値）」を手掛かりにして、バケツリレーのようにその場で評価を少しずつ修正する**手法。1歩ごとにリアルタイムで学習できるため、ステップ数が長い問題にも幅広く適用できる。
