6.2 探索と活用

上の例のように、どのマシンが当たりやすいか事前には分からない時、ランダムに選ぶよりも多くのコインを獲得する方法はあるでしょうか？

最初の何回か試しにスロットマシンを引いてみて、当たったか外れたかを見れば、そのマシンがどれくらい当たりやすいか見当をつけることができます。その後で一番当たりやすいと思われるマシンを引けば良さそうです。

ここで次の2つの欲求が衝突します：

  • 活用（Exploitation）: 「これまで引いた中で最も当たったマシンを引いて、確実に稼ぎたい」
  • 探索（Exploration）: 「まだあまり引いていない他のマシンを試せば、もっと当たりやすい最高のマシンが見つかるかもしれない」

過去の経験だけを信じて「活用」ばかりしていると、真の最高マシンを見逃してしまいます。逆に、「探索」ばかりしていると、ハズレ台を何度も引いてコインを無駄にしてしまいます。これが探索と活用のトレードオフです。

6.3 価値の推定（標本平均法）

あるマシンを選んだときに得られる報酬の期待値（価値）を、実際にプレイして得られた結果から推定することを考えます。

過去にそのマシンを \(n\) 回選び、得られた報酬が順に \(R_1, R_2, \dots, R_n\) だったとすると、推定価値 \(Q_n\) は平均値（標本平均）として求められます：

\[ Q_n = \frac{R_1 + R_2 + \dots + R_n}{n} = \frac{1}{n} \sum_{i=1}^{n} R_i \tag{6.1}\]

6.3.1 インクリメンタル（逐次的）な更新式の導出

新しい報酬 \(R_n\) が得られるたびに、過去の報酬を最初からすべて足し直して平均を計算するのは、計算の手間もメモリも無駄になります。 直前までの平均値 \(Q_{n-1}\) を使って、新しい平均値 \(Q_n\) を効率よく更新する式を導いてみましょう。

まず、最後の報酬 \(R_n\) だけを切り離します：

\[ Q_n = \frac{1}{n} \left( \sum_{i=1}^{n-1} R_i + R_n \right) \]

ここで、\(n-1\) 回目までの平均値 \(Q_{n-1} = \frac{1}{n-1} \sum_{i=1}^{n-1} R_i\) ですから、過去の報酬の合計は \(\sum_{i=1}^{n-1} R_i = (n-1) Q_{n-1}\) と表せます。これを代入します：

\[ Q_n = \frac{1}{n} \left( (n-1) Q_{n-1} + R_n \right) \]

展開して整理します：

\[ \begin{aligned} Q_n &= \frac{n-1}{n} Q_{n-1} + \frac{1}{n} R_n \\ &= \left( 1 - \frac{1}{n} \right) Q_{n-1} + \frac{1}{n} R_n \\ &= Q_{n-1} - \frac{1}{n} Q_{n-1} + \frac{1}{n} R_n \\ &= Q_{n-1} + \frac{1}{n} (R_n - Q_{n-1}) \end{aligned} \tag{6.2}\]

6.3.2 この式が表している意味

導出された更新式は、次のような構造をしています：

\[ \text{新しい推定値} \leftarrow \text{直前の推定値} + \frac{1}{n} \times \underbrace{\left( \text{今回の観測値} - \text{直前の推定値} \right)}_{\text{観測値と推定値のズレ（予測誤差）}} \]

  1. 観測値と推定値のズレ: \((R_n - Q_{n-1})\) は、「事前の予想（推定値）」に対して「実際に得られた結果（観測値）」がどれだけ違っていたかというズレ（予測誤差）を表します。
  2. ズレを少しだけ修正する: そのズレに \(\frac{1}{n}\)（ステップサイズ・重み）を掛けて足し合わせることで、直前の推定値を今回の結果に少し引き寄せます。試行回数 \(n\) が増えるほど \(\frac{1}{n}\) は小さくなるため、データが増えるにつれて推定値は安定していきます。
  3. メモリ効率: 過去のすべての報酬履歴（\(R_1, \dots, R_n\)）を記憶しておく必要がなく、「現在の推定値 \(Q\)」と「試行回数 \(n\)」の2つの数値さえあれば計算できます。

「実際に観測された値と現在の推定値とのズレを見て、そのズレを埋める方向に推定値を修正する」という更新の手法は、強化学習のアルゴリズムでよく使われます。

6.4 \(\epsilon\)-greedy法（イプシロン・グリーディ法）

探索と活用をバランスよく両立させる最も基本的な方策が \(\epsilon\)-greedy法（イプシロン・グリーディ法） です。

greedy（貪欲）とは「その時点で最も良さそうな選択肢をひたすら選ぶ（＝活用する）」という意味です。しかし、活用ばかりを優先していると、まだ試していない真の最高台を見逃してしまいます。

そこで、あらかじめ「探索（ランダムな選択）を行う確率」を決めておき、その確率をギリシャ文字の \(\epsilon\)（イプシロン） で表します。例えば、\(\epsilon = 0.1\)（10%の確率で探索）や \(\epsilon = 0.3\)（30%の確率で探索）のように小さな値を設定します。

6.4.1 乱数を使った意思決定の仕組み

コンピュータ上で「確率 \(\epsilon\) で探索し、確率 \(1 - \epsilon\) で活用する」という動作を実現するために、実際には毎回 0.0 から 1.0 までの実数の一様乱数 \(r\)を生成します（Pythonではrandom()）。

生成された乱数 \(r\) と設定した値 \(\epsilon\) を比べることで、次のように確率通りに振る舞いを切り替えます：

  • 乱数 \(r < \epsilon\) のとき（確率 \(\epsilon\)） \(\rightarrow\) 【探索（Exploration）】: すべてのマシンの中からランダムに1台を選びます。これにより、まだあまり引いていないマシンや、過去にたまたまハズレてしまったマシンを試すことができます。
  • 乱数 \(r \ge \epsilon\) のとき（確率 \(1 - \epsilon\)） \(\rightarrow\) 【活用（Exploitation）】: 現在までに推定された価値 \(Q(a)\) が最も高いマシンを選びます。これまでの経験上もっとも当たりやすい台で手堅くコインを稼ぎます。

例えば \(\epsilon = 0.3\) に設定した場合、0.0〜1.0 の乱数を引くと \(0.3\) 未満になる確率は 30%（探索）、\(0.3\) 以上になる確率は 70%（活用）となります。このようにして、サイコロを振るように探索と活用を自動的に切り替えています。

6.5 vibe codingによるシミュレーションの作成

前節までに学んだ「3台のスロットマシン」と「\(\epsilon\)-greedy法」を組み合わせたシミュレーションプログラムを、Antigravity（coding agent）を使って vibe coding で作成してみましょう。

第4回で学んだように、人間が一からコードを書くのではなく、「どのようなプログラムを作成したいか」という仕様・要件を自然言語で伝え、エージェントに対話形式でプログラムを構築・実行させます。

6.5.1 作成するプログラムの仕様

エージェントには以下の要件を満たすプログラムを作成してもらいます：

  1. 環境（スロットマシン）:
    • 3台のスロットマシン（マシン0: 20%、マシン1: 50%、マシン2: 80% の確率でコインが出る）。
    • エージェント（学習側）にはこの「真の確率」をあらかじめ教えません（引いてみて初めて当たり・ハズレが分かる）。
  2. 学習アルゴリズム（\(\epsilon\)-greedy法）:
    • 探索率 \(\epsilon = 0.1\)（10%の確率でランダム探索、90%の確率で現在推定値が最大のマシンを活用）。
    • コインが出れば報酬 \(1\)、出なければ \(0\) とし、逐次更新式（式 6.2）で推定価値 \(Q\) を更新する。
  3. シミュレーション実行:
    • 合計 1,000 ステップ試行する。
    • 終了後、各マシンの「真の確率」「最終的な推定価値」「選ばれた回数」を画面に分かりやすく表示する。

6.6.3 基本的な使い方（\(y = x^2\) のグラフを描く例）

まずは最もシンプルな例として、2次関数 \(y = x^2\) の折れ線グラフを描くPythonコードを見てみましょう。

import matplotlib.pyplot as plt

# 1. データの準備 (xの値と、それに対応する y = x^2 の値)
x = [-3, -2, -1, 0, 1, 2, 3]
y = [val ** 2 for val in x]  # [9, 4, 1, 0, 1, 4, 9]

# 2. グラフの描画設定
plt.plot(x, y, marker="o")      # xとyをプロットし、データ点に丸印をつける
plt.title("y = x^2")            # グラフのタイトル
plt.xlabel("x")                 # x軸のラベル
plt.ylabel("y")                 # y軸のラベル
plt.grid(True)                  # 目盛り線（グリッド）を表示

# 3. グラフの表示（または画像ファイルとして保存）
plt.show()                      # 画面にウィンドウを開いて表示
# plt.savefig("graph.png")      # 画像ファイルとして保存する場合はこちら

基本的な流れは次の4ステップです：

  1. インポート: import matplotlib.pyplot as plt で描画モジュールを plt という短い別名で読み込みます。
  2. データの用意: 横軸のリスト x と縦軸のリスト y を用意します。
  3. グラフの装飾: plt.plot(x, y) で線を引いた後、xlabel() や title() で説明を追加します。
  4. 出力: plt.show() で画面に表示するか、plt.savefig() で画像ファイルとして保存します。
ノートコラム：[val ** 2 for val in x] とは？（リスト内包表記）

コードの2行目に出てきた y = [val ** 2 for val in x] という書き方は、Python特有のリスト内包表記（List Comprehension）と呼ばれる構文です。

一見すると複雑に見えますが、パーツごとに分解すると非常にシンプルです：

  1. ** は「べき乗（2乗）」を表す演算子: Pythonでは ** はべき乗を意味します。val ** 2 は「val の 2乗（\(val^2\)）」を計算します。
  2. for val in x は「元のリストから1つずつ取り出す」: 元のリスト x = [-3, -2, -1, 0, 1, 2, 3] の先頭から、数値を順番に1つずつ取り出して変数 val に入れます。
  3. 全体を [ ] で囲んで「新しいリストにまとめる」: 取り出して2乗した計算結果（\(9, 4, 1, 0, 1, 4, 9\)）を並べた、新しいリスト y を作成します。

このリスト内包表記は、通常の for ループを使うと次のように書くのと同じ処理を行っています：

# 通常の for 文で書いた場合（3行必要）
y = []
for val in x:
    y.append(val ** 2)

通常の for 文では「空のリスト y = [] を用意し、ループの中で1つずつ .append() で末尾に追加する」という手順が必要ですが、リスト内包表記を使えばたった1行で簡潔に記述できます。

数学の集合の記法 \(\{ x^2 \mid x \in X \}\) にもよく似ており、Pythonのデータ処理や強化学習のコードで非常によく使われる表現です。

6.8 まとめ

  • 多腕バンディット問題: 未知の確率で報酬が得られる複数の選択肢（スロットマシン）から、限られた試行回数の中で累積報酬を最大化する強化学習の最も基本的な問題。
  • 探索と活用のトレードオフ: 「まだ試していない選択肢の情報を集めること（探索）」と「過去の経験から最も良いと分かっている選択肢を選ぶこと（活用）」のジレンマ。
  • 価値の推定と逐次更新式: 各行動の価値を「得られた報酬の平均値」で推定する。過去の全データを保持することなく、\(Q \leftarrow Q + \frac{1}{n}(R - Q)\)（または一定の学習率 \(\alpha\) を用いた式）によって逐次更新できる仕組みは、次章以降で学ぶ Q-learning などの強化学習アルゴリズムでも使われる。
  • \(\epsilon\)-greedy法: 乱数を利用し、確率 \(\epsilon\) でランダムに探索し、確率 \(1 - \epsilon\) で現在最も価値が高い行動を活用する代表的な行動選択戦略。\(\epsilon\) の設定次第で、局所解への固執（探索不足）や成果の頭打ち（探索過剰）が生じるため、適切なバランスが重要となる。
  • vibe codingと可視化: coding agent に対話的に指示を出してシミュレーションを構築・拡張し、Matplotlib による学習曲線の可視化を通してアルゴリズムの挙動やパラメータの影響を客観的に評価・分析する手法を体験した。

## 探索と活用

上の例のように、どのマシンが当たりやすいか事前には分からない時、ランダムに選ぶよりも多くのコインを獲得する方法はあるでしょうか？

最初の何回か試しにスロットマシンを引いてみて、当たったか外れたかを見れば、そのマシンがどれくらい当たりやすいか見当をつけることができます。その後で一番当たりやすいと思われるマシンを引けば良さそうです。

ここで次の2つの欲求が衝突します：

- **活用（Exploitation）**: 「これまで引いた中で最も当たったマシンを引いて、確実に稼ぎたい」
- **探索（Exploration）**: 「まだあまり引いていない他のマシンを試せば、もっと当たりやすい最高のマシンが見つかるかもしれない」

過去の経験だけを信じて「活用」ばかりしていると、真の最高マシンを見逃してしまいます。逆に、「探索」ばかりしていると、ハズレ台を何度も引いてコインを無駄にしてしまいます。これが**探索と活用のトレードオフ**です。

---

## 価値の推定（標本平均法）

あるマシンを選んだときに得られる報酬の期待値（価値）を、実際にプレイして得られた結果から推定することを考えます。

過去にそのマシンを $n$ 回選び、得られた報酬が順に $R_1, R_2, \dots, R_n$ だったとすると、推定価値 $Q_n$ は平均値（標本平均）として求められます：

$$
Q_n = \frac{R_1 + R_2 + \dots + R_n}{n} = \frac{1}{n} \sum_{i=1}^{n} R_i
$$ {#eq-mean}

### インクリメンタル（逐次的）な更新式の導出

新しい報酬 $R_n$ が得られるたびに、過去の報酬を最初からすべて足し直して平均を計算するのは、計算の手間もメモリも無駄になります。
直前までの平均値 $Q_{n-1}$ を使って、新しい平均値 $Q_n$ を効率よく更新する式を導いてみましょう。

まず、最後の報酬 $R_n$ だけを切り離します：

$$
Q_n = \frac{1}{n} \left( \sum_{i=1}^{n-1} R_i + R_n \right)
$$

ここで、$n-1$ 回目までの平均値 $Q_{n-1} = \frac{1}{n-1} \sum_{i=1}^{n-1} R_i$ ですから、過去の報酬の合計は $\sum_{i=1}^{n-1} R_i = (n-1) Q_{n-1}$ と表せます。これを代入します：

$$
Q_n = \frac{1}{n} \left( (n-1) Q_{n-1} + R_n \right)
$$

展開して整理します：

$$
\begin{aligned}
Q_n &= \frac{n-1}{n} Q_{n-1} + \frac{1}{n} R_n \\
    &= \left( 1 - \frac{1}{n} \right) Q_{n-1} + \frac{1}{n} R_n \\
    &= Q_{n-1} - \frac{1}{n} Q_{n-1} + \frac{1}{n} R_n \\
    &= Q_{n-1} + \frac{1}{n} (R_n - Q_{n-1})
\end{aligned}
$$ {#eq-incremental-mean}

### この式が表している意味

導出された更新式は、次のような構造をしています：

$$
\text{新しい推定値} \leftarrow \text{直前の推定値} + \frac{1}{n} \times \underbrace{\left( \text{今回の観測値} - \text{直前の推定値} \right)}_{\text{観測値と推定値のズレ（予測誤差）}}
$$

1. **観測値と推定値のズレ**:
   $(R_n - Q_{n-1})$ は、「事前の予想（推定値）」に対して「実際に得られた結果（観測値）」がどれだけ違っていたかというズレ（予測誤差）を表します。
2. **ズレを少しだけ修正する**:
   そのズレに $\frac{1}{n}$（ステップサイズ・重み）を掛けて足し合わせることで、直前の推定値を今回の結果に少し引き寄せます。試行回数 $n$ が増えるほど $\frac{1}{n}$ は小さくなるため、データが増えるにつれて推定値は安定していきます。
3. **メモリ効率**:
   過去のすべての報酬履歴（$R_1, \dots, R_n$）を記憶しておく必要がなく、「現在の推定値 $Q$」と「試行回数 $n$」の2つの数値さえあれば計算できます。

「**実際に観測された値と現在の推定値とのズレを見て、そのズレを埋める方向に推定値を修正する**」という更新の手法は、強化学習のアルゴリズムでよく使われます。

### 具体的な計算例（4回の試行）

あるスロットマシンを4回引いて、結果が **「ハズレ、当たり、当たり、ハズレ」** だった場合（当たり: $R=1$、ハズレ: $R=0$）の推定値の推移は次のようになります。

| 試行 ($n$) | 結果 | 観測値 $R_n$ | 更新式（@eq-incremental-mean）による計算 | 新しい推定値 $Q_n$ |
| :---: | :---: | :---: | :--- | :---: |
| 1 | ハズレ | $0$ | $Q_1 = 0$ | $0$ |
| 2 | 当たり | $1$ | $Q_2 = 0 + \frac{1}{2}(1 - 0) = \frac{1}{2}$ | $0.5$（$\frac{1}{2}$） |
| 3 | 当たり | $1$ | $Q_3 = \frac{1}{2} + \frac{1}{3}\left(1 - \frac{1}{2}\right) = \frac{1}{2} + \frac{1}{6}$ | 約 $0.67$（$\frac{2}{3}$） |
| 4 | ハズレ | $0$ | $Q_4 = \frac{2}{3} + \frac{1}{4}\left(0 - \frac{2}{3}\right) = \frac{2}{3} - \frac{1}{6}$ | $0.5$（$\frac{2}{4}$） |

通常の標本平均（@eq-mean）で検算してみると $Q_4 = \frac{0 + 1 + 1 + 0}{4} = 0.5$ となり、逐次更新の結果と一致することがわかります。

## $\epsilon$-greedy法（イプシロン・グリーディ法）

探索と活用をバランスよく両立させる最も基本的な方策が **$\epsilon$-greedy法（イプシロン・グリーディ法）** です。

greedy（貪欲）とは「その時点で最も良さそうな選択肢をひたすら選ぶ（＝活用する）」という意味です。しかし、活用ばかりを優先していると、まだ試していない真の最高台を見逃してしまいます。

そこで、**あらかじめ「探索（ランダムな選択）を行う確率」を決めておき、その確率をギリシャ文字の $\epsilon$（イプシロン）** で表します。例えば、$\epsilon = 0.1$（10%の確率で探索）や $\epsilon = 0.3$（30%の確率で探索）のように小さな値を設定します。

### 乱数を使った意思決定の仕組み

コンピュータ上で「確率 $\epsilon$ で探索し、確率 $1 - \epsilon$ で活用する」という動作を実現するために、実際には毎回 **0.0 から 1.0 までの実数の一様乱数 $r$**を生成します（Pythonでは`random()`）。

生成された乱数 $r$ と設定した値 $\epsilon$ を比べることで、次のように確率通りに振る舞いを切り替えます：

- **乱数 $r < \epsilon$ のとき（確率 $\epsilon$） $\rightarrow$ 【探索（Exploration）】**:
  すべてのマシンの中からランダムに1台を選びます。これにより、まだあまり引いていないマシンや、過去にたまたまハズレてしまったマシンを試すことができます。
- **乱数 $r \ge \epsilon$ のとき（確率 $1 - \epsilon$） $\rightarrow$ 【活用（Exploitation）】**:
  現在までに推定された価値 $Q(a)$ が最も高いマシンを選びます。これまでの経験上もっとも当たりやすい台で手堅くコインを稼ぎます。

例えば $\epsilon = 0.3$ に設定した場合、0.0〜1.0 の乱数を引くと $0.3$ 未満になる確率は 30%（探索）、$0.3$ 以上になる確率は 70%（活用）となります。このようにして、サイコロを振るように探索と活用を自動的に切り替えています。

$\epsilon$-greedy法がどのように探索と活用を切り替えながら学習を進めるのか、具体例で追ってみましょう。

#### 設定
- **スロットマシン**: マシンA、マシンB、マシンC の3台
- **探索率 $\epsilon$**: $0.3$（30%の確率で探索、70%の確率で活用）
- **初期推定値**: $Q(A) = 0,\ Q(B) = 0,\ Q(C) = 0$（試行回数はすべて0回）
- **意思決定ルール**:
  1. 毎回、0.00 〜 1.00 の一様乱数 $r$ を生成します。
  2. $r < 0.30$ なら「**探索**」とし、A・B・Cの3台からランダムに1台を選びます。
  3. $r \ge 0.30$ なら「**活用**」とし、その時点で推定値 $Q$ が最大のマシンを選びます（最大が複数ある場合はその中からランダムに選択）。

### コラム：`[val ** 2 for val in x]` とは？（リスト内包表記）

コードの2行目に出てきた `y = [val ** 2 for val in x]` という書き方は、Python特有の**リスト内包表記（List Comprehension）**と呼ばれる構文です。

一見すると複雑に見えますが、パーツごとに分解すると非常にシンプルです：

1. **`**` は「べき乗（2乗）」を表す演算子**:
   Pythonでは `**` はべき乗を意味します。`val ** 2` は「`val` の 2乗（$val^2$）」を計算します。
2. **`for val in x` は「元のリストから1つずつ取り出す」**:
   元のリスト `x = [-3, -2, -1, 0, 1, 2, 3]` の先頭から、数値を順番に1つずつ取り出して変数 `val` に入れます。
3. **全体を `[ ]` で囲んで「新しいリストにまとめる」**:
   取り出して2乗した計算結果（$9, 4, 1, 0, 1, 4, 9$）を並べた、新しいリスト `y` を作成します。

このリスト内包表記は、通常の `for` ループを使うと次のように書くのと同じ処理を行っています：

```python
# 通常の for 文で書いた場合（3行必要）
y = []
for val in x:
    y.append(val ** 2)
```

通常の `for` 文では「空のリスト `y = []` を用意し、ループの中で1つずつ `.append()` で末尾に追加する」という手順が必要ですが、リスト内包表記を使えば**たった1行で簡潔に記述**できます。

数学の集合の記法 $\{ x^2 \mid x \in X \}$ にもよく似ており、Pythonのデータ処理や強化学習のコードで非常によく使われる表現です。
:::

## まとめ

- **多腕バンディット問題**: 未知の確率で報酬が得られる複数の選択肢（スロットマシン）から、限られた試行回数の中で累積報酬を最大化する強化学習の最も基本的な問題。
- **探索と活用のトレードオフ**: 「まだ試していない選択肢の情報を集めること（探索）」と「過去の経験から最も良いと分かっている選択肢を選ぶこと（活用）」のジレンマ。
- **価値の推定と逐次更新式**: 各行動の価値を「得られた報酬の平均値」で推定する。過去の全データを保持することなく、$Q \leftarrow Q + \frac{1}{n}(R - Q)$（または一定の学習率 $\alpha$ を用いた式）によって逐次更新できる仕組みは、次章以降で学ぶ Q-learning などの強化学習アルゴリズムでも使われる。
- **$\epsilon$-greedy法**: 乱数を利用し、確率 $\epsilon$ でランダムに探索し、確率 $1 - \epsilon$ で現在最も価値が高い行動を活用する代表的な行動選択戦略。$\epsilon$ の設定次第で、局所解への固執（探索不足）や成果の頭打ち（探索過剰）が生じるため、適切なバランスが重要となる。
- **vibe codingと可視化**: coding agent に対話的に指示を出してシミュレーションを構築・拡張し、Matplotlib による学習曲線の可視化を通してアルゴリズムの挙動やパラメータの影響を客観的に評価・分析する手法を体験した。
