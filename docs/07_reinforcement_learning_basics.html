7  強化学習の基礎

7.1 強化学習のフレームワーク

強化学習では、意思決定を行う主体であるエージェント（Agent）と、エージェントが相互作用する対象である環境（Environment）が対話を繰り返します。前章の多腕バンディット問題との最大の違いは、エージェントの行動によって環境の「状態（状況）」が刻々と変化していくという点です。

時間 \(t = 0, 1, 2, \dots\) において：

  1. エージェントは現在の環境の状態 \(S_t\) を観測する。
  2. エージェントは方策に基づいて行動 \(A_t\) を決定し実行する。
  3. 環境は行動を受けて状態を更新し、新しい状態 \(S_{t+1}\) と即時報酬 \(R_{t+1}\) をエージェントに返す（そして \(S_{t+1}\) が次のステップの現在の状態となり、対話が繰り返される）。

7.1.1 マルコフ性（Markov Property）

上の図の下段にあるように、ステップ \(t = 0, 1, 2, \dots\) と進むにつれて状態は連鎖的に変化していきますが、この強化学習のフレームワークにはマルコフ性（Markov Property）という重要な前提があります。

マルコフ性とは 「次の状態 \(S_{t+1}\)（および報酬 \(R_{t+1}\)）が生じる確率は、直前の現在の状態 \(S_t\) と行動 \(A_t\) のみに依存し、それ以前の過去の履歴には一切依存しない」という性質です。

たとえば迷路の移動やボードゲームにおいて、「いまどのマスにいるか・いま盤面がどうなっているか（現在の状態 \(S_t\)）」さえ分かれば、そこに至るまでにどのような経路や手順をたどってきたか（過去の経緯）を記憶していなくても、将来の予測や最適な行動決定を行うことができます。このようにマルコフ性を満たす環境における意思決定の枠組みをマルコフ決定過程（MDP: Markov Decision Process）と呼びます。

7.2 状態・行動・報酬

強化学習の中核となる「状態・行動・報酬」の3つの概念を、次のような横一列に並んだ3つのマスの移動問題を例にして具体的に見ていきましょう。

  • マスの配置（状態ラベル）: 横一列に3つのマスがあり、エージェントがどのマスに居るかを状態として、左のマスから順に \(\text{A}, \text{B}, \text{C}\) とします。
  • 移動の選択肢（行動）: Right（右へ移動）と Left（左へ移動）の2つですが、右端の \(\text{C}\) に到達するとエピソード終了とし、そこからの行動は定義されません。
  • 評価のルール（報酬）: 1回の行動につき \(-1\)、そして \(\text{C}\) に到達したとき \(+10\) が与えられます。

7.2.1 状態（State: \(S\)）

エージェントが現在置かれている状況や局面の情報です（一般的にはマップ上の座標、盤面の駒の配置、ロボットの角度や速度などが該当します）。

  • 3マスの例における「状態」: エージェントがどのマスに居るかが状態であり、左のマスから順に \(\text{A}, \text{B}, \text{C}\) の3つの状態が存在します。
    • 状態 \(\text{A}\)（左のマス）・状態 \(\text{B}\)（中央のマス）: エージェントがこれから行動を選択する通常の状態です。
    • 状態 \(\text{C}\)（右のマス）: ここに到達すると1回分のプレイ（エピソード）が終了します。このような終了地点の状態を終端状態（Terminal State）と呼びます。
    • 時刻 \(t\) の状態 \(S_t\) との関係: \(S_t\)（\(S_0, S_1, S_2, \dots\)）は「ステップ \(t\) の時点でどの状態にいるか」を表す変数であり、その中身（値）として \(\text{A}, \text{B}, \text{C}\) が入ります。たとえば「時刻 \(t=0\) にマス \(\text{A}\) からスタートし、時刻 \(t=1\) にマス \(\text{B}\) へ移動した」場合、\(S_0 = \text{A},\; S_1 = \text{B}\) と表されます。

7.2.2 行動（Action: \(A\)）

エージェントが各状態において取ることができる選択肢です。

  • 3マスの例における「行動」: エージェントが選べる行動は Right（右のマスへ移動） と Left（左のマスへ移動） の2種類です。選ぶ行動によって、次の状態が以下のように変化します：
    • 状態 \(\text{A}\) のとき：Right を選ぶと \(\text{B}\) へ移動します。Left を選ぶとこれ以上左にマスがないため、壁に阻まれて \(\text{A}\) に留まります（例：\(S_0 = \text{A}\) で \(A_0 = \text{Left}\) を選ぶと、次の時刻も \(S_1 = \text{A}\) となります）。
    • 状態 \(\text{B}\) のとき：Right を選ぶと \(\text{C}\) へ移動し、Left を選ぶと \(\text{A}\) へ戻ります。
    • 状態 \(\text{C}\) のとき：\(\text{C}\) に到達した時点でエピソード終了となるため、\(\text{C}\) からの行動は定義されません。

7.2.3 報酬（Reward: \(R\)）

行動の結果として環境からエージェントに与えられる即時の数値的な評価です。エージェントにとっての「ご褒美（プラス値）」や「ペナルティ・コスト（マイナス値）」を表します。

  • 3マスの例における「報酬」: 次の2つのルールで報酬が与えられます：
    1. 1回の行動につき \(-1\)：Right または Left を1回実行するたびに、移動コスト（時間経過のペナルティ）として \(-1\) が与えられます。もしこの \(-1\) がなければ、エージェントは何百回も左右にウロウロしてからゴールしても損をしないことになりますが、1手ごとに \(-1\) されることで「できるだけ少ない手数（最短経路）でゴールする」ことが促されます。
    2. \(\text{C}\) に到達したとき \(+10\)：ゴールである \(\text{C}\) に到達したときに、目標達成のご褒美として \(+10\) が与えられます。
    • したがって、各行動をとった直後に得られる報酬は、通常の移動（\(\text{A} \to \text{B}\) や \(\text{B} \to \text{A}\)、\(\text{A} \to \text{A}\)）では \(-1\) となり、\(\text{B}\) から Right を選んで \(\text{C}\) に到達したステップでは、1回分の行動に対する \(-1\) と \(\text{C}\) 到達の \(+10\) を合わせて \(-1 + 10 = +9\) となります。

7.3 方策と収益

「状態・行動・報酬」という環境のルールが定まったところで、次はエージェント側の「行動の選び方（方策）」と、その良し悪しを測る「獲得報酬の合計（収益）」について見ていきましょう。

7.3.1 方策（Policy: \(\pi\)）

エージェントが「どの状態において、どの行動を選ぶか」を定めた行動のルール（戦略）を方策（Policy）と呼び、ギリシャ文字の \(\pi\)（パイ）で表します。

ここでは、各状態 \(s\) に対して取るべき行動 \(a\) がただ1つに決まっている決定的方策（Deterministic Policy）を考えます。数式では関数のように次のように表します：

\[ a = \pi(s) \]

先ほどの3マスの移動問題では、行動を選択する状態は \(\text{A}\) と \(\text{B}\) の2つ（状態 \(\text{C}\) はエピソード終了のため行動なし）であり、それぞれ Right か Left を選べるため、決定的方策は全部で \(2 \times 2 = 4\) 通り存在します。

7.3.2 収益（Return: \(G_t\)）と方策ごとの計算例

強化学習におけるエージェントの目的は、目の前の1ステップの報酬だけではなく、エピソード終了までに将来にわたって得られる報酬の総和を最大化することです。この累積報酬を収益（Return）と呼び、\(G_t\) で表します。

まずは割引を考えない単純な報酬の足し算（\(G_0 = R_1 + R_2 + R_3 + \dots\)）として、代表的な2つの方策で状態 \(\text{A}\) からスタート（\(S_0 = \text{A}\)）したときの収益 \(G_0\) を計算してみましょう。

7.3.2.1 状態 \(\text{A}, \text{B}\) で Right という方策のとき

状態 \(\text{A}\) でも状態 \(\text{B}\) でも常に Right を選ぶ方策（\(\pi(\text{A}) = \text{Right},\; \pi(\text{B}) = \text{Right}\)）に従い、状態 \(\text{A}\)（\(S_0 = \text{A}\)）からスタートします。

  1. 1ステップ目（\(t = 0 \to 1\)）：状態 \(\text{A}\) で Right を選び、状態 \(\text{B}\)（\(S_1 = \text{B}\)）へ移動します。1回の行動につき \(-1\) の報酬が与えられるため、\(R_1 = -1\) です。
  2. 2ステップ目（\(t = 1 \to 2\)）：状態 \(\text{B}\) で Right を選び、状態 \(\text{C}\)（\(S_2 = \text{C}\)）へ到達します。行動1回分の \(-1\) と状態 \(\text{C}\) 到達の \(+10\) により \(R_2 = -1 + 10 = +9\) を得て、ここでエピソード終了となります。

したがって、単純に報酬を足し合わせた場合の収益 \(G_0\) は次のようになります：

\[ G_0 = R_1 + R_2 = (-1) + 9 = +8 \]

7.3.2.2 状態 \(\text{A}, \text{B}\) で Left という方策のとき

次に、状態 \(\text{A}\) でも状態 \(\text{B}\) でも常に Left を選ぶ方策（\(\pi(\text{A}) = \text{Left},\; \pi(\text{B}) = \text{Left}\)）に従い、同じく状態 \(\text{A}\)（\(S_0 = \text{A}\)）からスタートしてみます。

  1. 1ステップ目（\(t = 0 \to 1\)）：状態 \(\text{A}\) で Left を選びますが、左端の壁に阻まれて状態 \(\text{A}\)（\(S_1 = \text{A}\)）に留まります。報酬は \(R_1 = -1\) です。
  2. 2ステップ目（\(t = 1 \to 2\)）：再び状態 \(\text{A}\) にいるため、方策に従ってまた Left を選び、状態 \(\text{A}\)（\(S_2 = \text{A}\)）に留まって報酬 \(R_2 = -1\) を得ます。
  3. 3ステップ目以降：この後も永久に状態 \(\text{A}\) で Left を選び続け、いつまでも状態 \(\text{C}\) に到達しないため、エピソードが永遠に終わりません。

このとき、報酬を単純に足し合わせようとすると、

\[ G_0 = R_1 + R_2 + R_3 + \dots = (-1) + (-1) + (-1) + \dots = -\infty \]

となり、収益が無限大（\(-\infty\)）に発散してしまいます。収益が発散してしまうと、方策どうしの良し悪しを数値として比較したり計算したりすることができなくなります。

7.3.3 割引率（Discount Factor: \(\gamma\)）の導入

このようにエピソードが無限に続く場合でも収益が発散することを防ぎ、有限の数値として計算できるようにするために導入されるのが割引率（Discount Factor）\(\gamma\)（ガンマ、\(0 \le \gamma < 1\)）です。

将来の報酬ほど時間経過に伴って価値が割り引かれると考え、1ステップ先になるごとに報酬に \(\gamma\) を掛け合わせて収益 \(G_t\) を定義します：

\[ G_t = R_{t+1} + \gamma R_{t+2} + \gamma^2 R_{t+3} + \dots = \sum_{k=0}^{\infty} \gamma^k R_{t+k+1} \]

直感的理解: 今すぐもらえる100円と、遠い将来にもらえる100円では現在の価値が異なるのと同じです。\(\gamma\) が \(0\) に近いと「目先の報酬だけを重視」し、\(\gamma\) が \(1\) に近い（通常 \(0.9 \sim 0.99\)）と「将来の報酬も重視」します。

7.3.4 割引率 \(\gamma = 0.9\) で収益を計算してみる

それでは、割引率を \(\gamma = 0.9\) に設定して、先ほどの2つの方策で状態 \(\text{A}\) からスタートしたときの収益 \(G_0\) を改めて計算してみましょう。

7.3.4.1 状態 \(\text{A}, \text{B}\) で Right という方策（\(\gamma = 0.9\)）

2ステップでゴールに到達して終了するため、項は \(R_1 = -1\) と \(R_2 = +9\) の2つだけです。2ステップ目の報酬 \(R_2\) に \(\gamma = 0.9\) が1回掛けられます：

\[ G_0 = R_1 + \gamma R_2 = (-1) + 0.9 \times 9 = -1 + 8.1 = \mathbf{7.1} \]

7.3.4.2 状態 \(\text{A}, \text{B}\) で Left という方策（\(\gamma = 0.9\)）

毎ステップ \(R_1 = -1,\; R_2 = -1,\; R_3 = -1, \dots\) が無限に続きますが、1ステップごとに \(0.9\) 倍ずつ割り引かれるため、発散せずに有限の値に収束します：

\[ \begin{aligned} G_0 &= R_1 + \gamma R_2 + \gamma^2 R_3 + \gamma^3 R_4 + \dots \\ &= (-1) + 0.9 \times (-1) + 0.9^2 \times (-1) + 0.9^3 \times (-1) + \dots \\ &= (-1) \times \left(1 + 0.9 + 0.9^2 + 0.9^3 + \dots \right) \end{aligned} \]

ここで、カッコの中身は初項 \(1\)・公比 \(0.9\) の無限等比級数（\(1 + \gamma + \gamma^2 + \dots = \dfrac{1}{1 - \gamma}\)）なので、

\[ G_0 = (-1) \times \frac{1}{1 - 0.9} = (-1) \times \frac{1}{0.1} = \mathbf{-10} \]

と求めることができます。

ヒント別解：再帰的な関係式を使って求める方法

無限等比級数の公式を覚えていなくても、次のような工夫で簡単に計算できます。 \(G_0\) の式の2項目以降を \(0.9\) でくくると、カッコの中身は元の \(G_0\) とまったく同じ形になります：

\[ \begin{aligned} G_0 &= -1 + 0.9 \times \underbrace{\left( -1 + 0.9 \times (-1) + 0.9^2 \times (-1) + \dots \right)}_{=\, G_0} \\ G_0 &= -1 + 0.9\, G_0 \end{aligned} \]

この1次方程式を解くと、\(0.1\, G_0 = -1\) より \(G_0 = -10\) がすぐに得られます。「現在の収益 ＝ 直後の報酬 ＋ \(\gamma \times\) 次のステップからの収益」というこの関係は、強化学習において極めて重要な性質です。

  1. 方策①（状態 \(\text{A}, \text{B}\) ともに Right）に従うとき、中央の状態 \(\text{B}\) からスタート（\(S_0 = \text{B}\)）した場合の収益 \(G_0\) はいくらになりますか？

7.4 確率的な状態遷移

これまでの説明では、状態 \(\text{A}\) で Right を選べば 100%確実に 状態 \(\text{B}\) へ移動できるように、「現在の状態と行動が決まれば、次の状態がただ1つに確定する」という前提で考えてきました。このような環境を決定的（Deterministic）な環境と呼びます。

しかし、現実世界や多くのゲーム環境では、エージェントが意図したとおりに100%確実に移動できるとは限りません。

  • 車輪ロボットが前進しようとしても、床が濡れていてその場でスリップ（空回り）してしまう。
  • ドローンや自動運転車が、突風や路面の状況によって意図した位置へ進めない。
  • ゲームにおいて、氷の上を歩くキャラクターが一定の確率で滑ってその場にとどまったり、別の方向へ流されたりする。

このように、ある状態で行動を実行したとき、次の状態が確率的に決まる仕組みを確率的な状態遷移（Stochastic State Transition）と呼びます。

ヒント確率的な状態遷移でも「マルコフ性」は成り立つ

状態遷移が確率的であっても、「次の状態 \(S_{t+1}\) がどの状態になるかの確率」が直前の状態 \(S_t\) と行動 \(A_t\) のみによって決まり、それ以前の過去の履歴に依存しないならば、マルコフ性は満たされています。

7.4.1 例：20%の確率でその場にとどまる環境

先ほどの3マスの移動問題に、「床が滑りやすく、移動しようとしても 20%（確率 \(0.2\)）で失敗してその場にとどまり、80%（確率 \(0.8\)）で意図した方向へ移動できる」という確率的な状態遷移を取り入れてみましょう。

この環境では、各状態において行動を選んだときの結果が次のように分かれます（行動を1回実行するたびに \(-1\)、状態 \(\text{C}\) に到達したときだけ \(+10\) が加わるルールは同じです）：

  • 状態 \(\text{A}\) で Right を選んだとき：
    • 80%（確率 \(0.8\)）で右の状態 \(\text{B}\) へ移動します（報酬 \(-1\)）。
    • 20%（確率 \(0.2\)）でその場（状態 \(\text{A}\)）にとどまります。移動できなくても1回分の行動を実行したため、報酬は \(-1\) です。
  • 状態 \(\text{B}\) で Right を選んだとき：
    • 80%（確率 \(0.8\)）で右の状態 \(\text{C}\)（ゴール）へ到達し、エピソード終了となります（報酬 \(-1 + 10 = \mathbf{+9}\)）。
    • 20%（確率 \(0.2\)）でその場（状態 \(\text{B}\)）にとどまります（報酬 \(-1\)）。
  • 状態 \(\text{B}\) で Left を選んだとき：
    • 80%（確率 \(0.8\)）で左の状態 \(\text{A}\) へ移動します（報酬 \(-1\)）。
    • 20%（確率 \(0.2\)）でその場（状態 \(\text{B}\)）にとどまります（報酬 \(-1\)）。
  • 状態 \(\text{A}\) で Left を選んだとき：
    • 左に壁があるため、80%の移動と20%のスリップのどちらが起きても 100%（確率 \(1.0\)）の確率で状態 \(\text{A}\) にとどまります（報酬 \(-1\)）。

7.4.2 同じ方策でも試行ごとに経路と収益 \(G_0\) が変わる

状態遷移が確率的になると、エージェントがまったく同じ方策に従って行動していても、エピソード（試行）ごとにたどる経路や得られる収益 \(G_0\) が確率的に変化します。

具体例として、先ほどと同じ 方策①（状態 \(\text{A}, \text{B}\) ともに Right を選ぶ：\(\pi(\text{A}) = \text{Right},\; \pi(\text{B}) = \text{Right}\)） に従い、状態 \(\text{A}\)（\(S_0 = \text{A}\)）からスタートした場合（割引率 \(\gamma = 0.9\)）を考えてみましょう。

7.4.2.1 経路パターン1：1度も滑らずに2ステップでゴールする場合（\(\text{A} \to \text{B} \to \text{C}\)）

  • 1ステップ目（\(t = 0 \to 1\)）：状態 \(\text{A}\) で Right を選び、80%（\(0.8\)）の確率で状態 \(\text{B}\) へ移動します（\(R_1 = -1\)）。
  • 2ステップ目（\(t = 1 \to 2\)）：状態 \(\text{B}\) で Right を選び、80%（\(0.8\)）の確率で状態 \(\text{C}\) へ到達して終了します（\(R_2 = +9\)）。
  • この経路をたどる確率： \[ 0.8 \times 0.8 = 0.64 \quad (\mathbf{64\%}) \]
  • このときの収益 \(G_0\)： \[ G_0 = R_1 + \gamma R_2 = (-1) + 0.9 \times 9 = \mathbf{7.1} \]

7.4.2.2 経路パターン2：最初に状態 \(\text{A}\) で1回とどまり、3ステップでゴールする場合（\(\text{A} \to \text{A} \to \text{B} \to \text{C}\)）

  • 1ステップ目（\(t = 0 \to 1\)）：状態 \(\text{A}\) で Right を選びますが、20%（\(0.2\)）の確率で滑って状態 \(\text{A}\) にとどまります（\(R_1 = -1\)）。
  • 2ステップ目（\(t = 1 \to 2\)）：再び状態 \(\text{A}\) で Right を選び、今度は80%（\(0.8\)）の確率で状態 \(\text{B}\) へ移動します（\(R_2 = -1\)）。
  • 3ステップ目（\(t = 2 \to 3\)）：状態 \(\text{B}\) で Right を選び、80%（\(0.8\)）の確率で状態 \(\text{C}\) へ到達して終了します（\(R_3 = +9\)）。
  • この経路をたどる確率： \[ 0.2 \times 0.8 \times 0.8 = 0.128 \quad (\mathbf{12.8\%}) \]
  • このときの収益 \(G_0\)：1ステップ余計にかかったため、移動コスト \(-1\) が増えるとともに、ゴール時の報酬 \(+9\) が \(\gamma^2 = 0.9^2 = 0.81\) 倍に割り引かれます： \[ G_0 = R_1 + \gamma R_2 + \gamma^2 R_3 = (-1) + 0.9 \times (-1) + 0.9^2 \times 9 = -1 - 0.9 + 7.29 = \mathbf{5.39} \]

このように、確率的な状態遷移をもつ環境では、同じ方策 \(\pi\) に従っていても、1回のエピソードで得られる収益 \(G_t\) は試行ごとに異なる値（確率変数）になります。

ノート練習問題 07-03：確率的な状態遷移での確率と収益

20%の確率でその場にとどまる環境において、方策①（状態 \(\text{A}, \text{B}\) ともに Right）に従い、状態 \(\text{A}\) からスタート（\(S_0 = \text{A}\)）したとします（割引率 \(\gamma = 0.9\)）。

  1. 上の図の【経路パターン3】のように、「1ステップ目で状態 \(\text{A}\) から \(\text{B}\) へ移動できたものの、2ステップ目で状態 \(\text{B}\) にとどまり、3ステップ目で状態 \(\text{C}\) に到達した」場合（経路：\(\text{A} \to \text{B} \to \text{B} \to \text{C}\)）、この経路をたどる確率は何%ですか？また、このときの収益 \(G_0\) はいくらになりますか？
  2. 合計3ステップでゴール（状態 \(\text{C}\) に到達）する経路は、パターン2（\(\text{A} \to \text{A} \to \text{B} \to \text{C}\)）とパターン3（\(\text{A} \to \text{B} \to \text{B} \to \text{C}\)）の2通りあります。では、合計4ステップでゴールする経路は何通りあり、それぞれどのような状態の列になりますか？

7.5 確率的な方策

前節では「環境側の状態遷移」が確率的になる場合を見ましたが、エージェント側の行動ルールである「方策（Policy）」そのものが確率的になる場合もあります。

「方策と収益」の節では、各状態 \(s\) に対して取るべき行動が \(a = \pi(s)\) のようにただ1つに決まっている決定的方策（Deterministic Policy）を扱いました。これに対し、「ある状態 \(s\) にいるとき、各行動 \(a\) をそれぞれどのくらいの確率で選ぶか」を定めた方策を確率的方策（Stochastic Policy）と呼び、状態 \(s\) で行動 \(a\) を選ぶ確率を次のように表します：

\[ \pi(a \mid s) \]

たとえば、状態 \(\text{A}\) において Right を選ぶ確率と Left を選ぶ確率がそれぞれ \(50\%\)（\(0.5\)）である場合、\(\pi(\text{Right} \mid \text{A}) = 0.5,\; \pi(\text{Left} \mid \text{A}) = 0.5\) と表します（同じ状態で選びうるすべての行動の選択確率を足し合わせると必ず \(1\) になります）。

ヒントなぜ確率的な方策を使うのか？
  1. 探索（Exploration）を行うため：前章の多腕バンディット問題で学んだ \(\varepsilon\)-greedy 法のように、未知の状況を試してより良い経路を発見するためには、一定の確率でランダムに行動を選ぶ必要があります。特に学習開始時は、まだどの行動が良いか分からないため、完全にランダムに行動を選ぶ方策からスタートするのが一般的です。
  2. 対戦ゲームなどで裏をかくため：じゃんけんやカードゲームのように相手がいる環境では、いつも同じ行動をとる決定的方策だと相手に先読みされてしまうため、確率的に行動を散らす方策が有効になります。

7.5.1 例：ランダムに行動を選ぶ方策（50%ずつ Right と Left を選択）

ここでは、確率的方策の働きを分かりやすく見るため、環境の状態遷移は決定的（選んだ行動の方向へ100%確実に移動する）に戻し、エージェントが状態 \(\text{A}\) でも状態 \(\text{B}\) でも 50%（確率 \(0.5\)）ずつランダムに Right または Left を選ぶ方策を考えてみましょう。

\[ \pi(\text{Right} \mid \text{A}) = 0.5, \quad \pi(\text{Left} \mid \text{A}) = 0.5 \] \[ \pi(\text{Right} \mid \text{B}) = 0.5, \quad \pi(\text{Left} \mid \text{B}) = 0.5 \]

7.5.2 環境が決定的でも、確率的方策によって経路と収益 \(G_0\) が変わる

環境の状態遷移が100%決定的であっても、エージェント自身が確率的に行動を選ぶため、エピソード（試行）ごとに選ばれる行動の列が変わり、たどる経路と収益 \(G_0\) が確率的に変化します。

このランダム方策に従い、状態 \(\text{A}\)（\(S_0 = \text{A}\)）からスタートした場合（割引率 \(\gamma = 0.9\)）の代表的な経路パターンを見てみましょう。

7.5.2.1 経路パターン1：2回連続で Right を選び、2ステップでゴールする場合（\(\text{A} \to \text{B} \to \text{C}\)）

  • 1ステップ目（\(t = 0 \to 1\)）：状態 \(\text{A}\) で 50%（\(0.5\)）の確率で Right を選び、状態 \(\text{B}\) へ移動します（\(R_1 = -1\)）。
  • 2ステップ目（\(t = 1 \to 2\)）：状態 \(\text{B}\) で 50%（\(0.5\)）の確率で Right を選び、状態 \(\text{C}\) へ到達して終了します（\(R_2 = +9\)）。
  • この経路をたどる確率： \[ 0.5 \times 0.5 = 0.25 \quad (\mathbf{25\%}) \]
  • このときの収益 \(G_0\)： \[ G_0 = R_1 + \gamma R_2 = (-1) + 0.9 \times 9 = \mathbf{7.1} \]

7.5.2.2 経路パターン2：最初に状態 \(\text{A}\) で Left を選び、3ステップでゴールする場合（\(\text{A} \to \text{A} \to \text{B} \to \text{C}\)）

  • 1ステップ目（\(t = 0 \to 1\)）：状態 \(\text{A}\) で 50%（\(0.5\)）の確率で Left を選び、左の壁に阻まれて状態 \(\text{A}\) にとどまります（\(R_1 = -1\)）。
  • 2ステップ目（\(t = 1 \to 2\)）：状態 \(\text{A}\) で 50%（\(0.5\)）の確率で Right を選び、状態 \(\text{B}\) へ移動します（\(R_2 = -1\)）。
  • 3ステップ目（\(t = 2 \to 3\)）：状態 \(\text{B}\) で 50%（\(0.5\)）の確率で Right を選び、状態 \(\text{C}\) へ到達して終了します（\(R_3 = +9\)）。
  • この経路をたどる確率： \[ 0.5 \times 0.5 \times 0.5 = 0.125 \quad (\mathbf{12.5\%}) \]
  • このときの収益 \(G_0\)： \[ G_0 = R_1 + \gamma R_2 + \gamma^2 R_3 = (-1) + 0.9 \times (-1) + 0.9^2 \times 9 = -1 - 0.9 + 7.29 = \mathbf{5.39} \]

さらに、上の図の【経路パターン3】（\(\text{A} \to \text{B} \to \text{A} \to \text{B} \to \text{C}\)）のように、状態 \(\text{B}\) で Left（50%）を選んだ場合は状態 \(\text{A}\) へ逆戻りすることになります。

このように、「環境の状態遷移が確率的である場合」だけでなく、「エージェントの方策が確率的である場合」（あるいはその両方である場合）にも、1回のエピソードで得られる収益 \(G_t\) は試行ごとにばらつくことになります。

ノート練習問題 07-04：ランダム方策での確率と収益

決定的な状態遷移（選んだ方向へ100%移動する環境）において、50%ずつランダムに Right または Left を選ぶ方策に従い、状態 \(\text{A}\) からスタート（\(S_0 = \text{A}\)）したとします（割引率 \(\gamma = 0.9\)）。

  1. 上の図の【経路パターン3】のように、Right \(\to\) Left \(\to\) Right \(\to\) Right の順に行動を選んで4ステップでゴールした場合（経路：\(\text{A} \to \text{B} \to \text{A} \to \text{B} \to \text{C}\)）、この経路をたどる確率は何%ですか？また、このときの収益 \(G_0\) はいくらになりますか？（ヒント：\(0.9^3 = 0.729\)）

7.6 確率的な状態遷移と確率的な方策

ここまでの2つの節では、「環境の状態遷移だけが確率的な場合（方策は決定的）」と「エージェントの方策だけが確率的な場合（環境は決定的）」をそれぞれ個別に見てきました。

しかし、実際の強化学習では「環境の状態遷移が確率的」であり、かつ「エージェントの方策も確率的」という状況がごく一般的に現れます。たとえば、滑りやすい床や風が吹く環境の中で、エージェントが未知の状況を探索するためにランダム性を交えて行動を選択する場合などがこれにあたります。

このように両方とも確率的である場合、現在の状態 \(S_t\) から次の状態 \(S_{t+1}\) が決まるまでに、次の2段階の確率的な枝分かれが順番に起こります：

  1. 第1段階（エージェントの方策 \(\pi\)）：現在の状態 \(S_t\) において、エージェントが確率的方策 \(\pi(a \mid s)\) に従って行動 \(A_t\) を確率的に選ぶ。
  2. 第2段階（環境の状態遷移）：選ばれた行動 \(A_t\) に対して、環境が状態遷移確率に従って次の状態 \(S_{t+1}\)（と報酬 \(R_{t+1}\)）を確率的に決める。

7.6.1 状態 \(\text{A}\) から次の状態が決まる様子

これまでの2つの例を組み合わせて、次の設定で状態 \(\text{A}\)（\(S_t = \text{A}\)）から1ステップ後の状態 \(S_{t+1}\) が決まる様子を具体的に追ってみましょう。

  • エージェント（確率的方策）：各状態で Right を 50%（\(0.5\)）、Left を 50%（\(0.5\)） の確率で選ぶ。
  • 環境（確率的状態遷移）：選んだ方向へ 80%（\(0.8\)）の確率で移動し、20%（\(0.2\)）の確率でスリップしてその場に留まる（ただし状態 \(\text{A}\) の左には壁があるため、Left を選んだ場合は移動しようとしても壁に阻まれて状態 \(\text{A}\) に留まる）。

このとき、状態 \(\text{A}\) から次の状態 \(S_{t+1}\) が決まるまでの過程を枝分かれの図（樹形図）として描くと、次のようになります。

上の枝分かれの図を左から順にたどると、各枝の確率と最終的な次の状態 \(S_{t+1}\) の確率は次のように計算できます：

  1. 行動 Right（選択確率 \(50\% = 0.5\)）を選んだ場合：
    • 80%（\(0.8\)）で移動に成功：次の状態は \(S_{t+1} = \text{B}\)（報酬 \(R_{t+1} = -1\)）となります。この枝をたどる確率は、行動を選ぶ確率と状態遷移の確率を掛け合わせて \[ 0.5 \times 0.8 = 0.40 \quad (\mathbf{40\%}) \]
    • 20%（\(0.2\)）でスリップ：次の状態は \(S_{t+1} = \text{A}\)（報酬 \(R_{t+1} = -1\)）のままとなります。この枝をたどる確率は \[ 0.5 \times 0.2 = 0.10 \quad (\mathbf{10\%}) \]
  2. 行動 Left（選択確率 \(50\% = 0.5\)）を選んだ場合：
    • 左に動こうとして壁に阻まれる場合（\(80\%\)）も、スリップする場合（\(20\%\)）も、どちらも次の状態は \(S_{t+1} = \text{A}\)（報酬 \(R_{t+1} = -1\)）となります。したがって、Left を選んで状態 \(\text{A}\) に留まる確率は \[ 0.5 \times 0.8 + 0.5 \times 0.2 = 0.40 + 0.10 = 0.50 \quad (\mathbf{50\%}) \] （最初から「Left を選べば \(100\%\)（\(1.0\)）の確率で \(\text{A}\) に留まる」と考えて \(0.5 \times 1.0 = 0.50\) と計算しても同じです。）
  3. 次の状態 \(S_{t+1}\) ごとに確率をまとめる： 注目すべき点は、「Right を選んだけれどスリップしたケース（\(10\%\)）」と「Left を選んで留まったケース（\(50\%\)）」という異なる枝から、どちらも同じ状態 \(\text{A}\) に到達していることです。これらを足し合わせると、状態 \(\text{A}\) から1ステップ進んだ後の状態 \(S_{t+1}\) の確率分布は次のようになります：
    • 状態 \(\text{B}\) へ進む確率：\(40\%\)（\(0.4\)）
    • 状態 \(\text{A}\) に留まる確率：\(10\% + 50\% = \mathbf{60\%}\)（\(0.6\)）

7.6.2 エピソード全体の経路の確率と収益 \(G_0\)

同様に、中央の状態 \(\text{B}\) にいるときも「① 行動の選択（Right \(50\%\) ／ Left \(50\%\)）」と「② 環境の状態遷移（移動成功 \(80\%\) ／ スリップ \(20\%\)）」の2段階の枝分かれが起こります。たとえば状態 \(\text{B}\) から1ステップでゴール（状態 \(\text{C}\)）へ到達するには、状態 \(\text{B}\) で Right（\(50\%\)）を選び、かつ滑らずに移動（\(80\%\)）する必要があるため、その確率は \(0.5 \times 0.8 = 0.40\)（\(40\%\)）となります。

これを使うと、状態 \(\text{A}\) からスタート（\(S_0 = \text{A}\)）したときの各経路の確率と収益 \(G_0\)（割引率 \(\gamma = 0.9\)）もこれまでと同じように計算できます：

  • 最短の2ステップでゴールする場合（\(\text{A} \to \text{B} \to \text{C}\)）：
    • 1ステップ目に \(\text{A} \to \text{B}\) となる確率が \(40\%\)（\(0.4\)）、2ステップ目に \(\text{B} \to \text{C}\) となる確率も \(40\%\)（\(0.4\)） なので、この経路をたどる確率は \[ 0.4 \times 0.4 = 0.16 \quad (\mathbf{16\%}) \]
    • 収益はこれまでと同じく \(G_0 = (-1) + 0.9 \times 9 = \mathbf{7.1}\) です。
  • 最初に状態 \(\text{A}\) に1回留まり、3ステップでゴールする場合（\(\text{A} \to \text{A} \to \text{B} \to \text{C}\)）：
    • 1ステップ目に \(\text{A} \to \text{A}\) となる確率は、Right で滑る確率（\(10\%\)）と Left で留まる確率（\(50\%\)）を合わせた \(60\%\)（\(0.6\)） です。その後 \(\text{A} \to \text{B}\)（\(0.4\)）、\(\text{B} \to \text{C}\)（\(0.4\)）と進むため、合計の確率は \[ 0.6 \times 0.4 \times 0.4 = 0.096 \quad (\mathbf{9.6\%}) \]
    • 収益は \(G_0 = (-1) + 0.9 \times (-1) + 0.9^2 \times 9 = \mathbf{5.39}\) です。

7.8 2Dゲーム・アニメーションライブラリ Pygame とは？

前節ではターミナル上に文字でエージェントの移動履歴を表示しましたが、強化学習の実験ではエージェントが環境の中で実際にどのように動いているかをアニメーション（映像）として視覚的に確認することが非常に役立ちます。文字だけでは気づきにくい「同じ場所をウロウロしている」「壁にぶつかり続けている」といった振る舞いも、画面上で動いている様子を見れば一目で直感的に把握できます。

Pythonで2Dゲームやアニメーションを手軽に作成・描画できる代表的な外部ライブラリが Pygame（パイゲーム） です。

  • Pygame でできること: 専用のウィンドウを開き、円や四角形などの図形・テキスト・画像を自由な位置に描画して、1秒間に何十回も画面を書き換えることで滑らかなアニメーションを実現できます。キーボードやマウスの操作を受け取ることも可能です。
  • 強化学習との関わり: 第8回以降で使用する強化学習の標準ライブラリ Gymnasium でも、内部で環境の画面描画（レンダリング）を行うために Pygame が広く使われています。

7.8.2 Pygame の画面座標系とアニメーションの仕組み

Pygame で図形を動かす際にまず押さえておくべき重要なルールが「画面の座標系」です。

数学のグラフ（Matplotlib など）では「左下」や「中央」を原点 \((0, 0)\) とし、上へ行くほど \(y\) 座標が大きくなります。しかし、Pygame（および多くのコンピュータ画面）では「左上隅が原点 \((0, 0)\)」となり、右へ行くほど \(x\) 座標が大きく、下へ行くほど \(y\) 座標が大きくなるという特徴があります。

また、アニメーションは「① 背景色で画面全体を塗りつぶして前の絵を消す \(\to\) ② 座標 \((x, y)\) を少し変化させる \(\to\) ③ 新しい座標に図形を描く \(\to\) ④ 画面を更新して少し待つ」という処理を、while ループ（メインループ）の中で1秒間に60回（60 FPS: Frames Per Second）などの一定ペースで繰り返すことで動いて見えます（パラパラ漫画と同じ仕組みです）。

7.8.3 基本的な使い方（円が左上から右下へ移動する例）

簡単な例として、青い円が画面の左上 \((0, 0)\) から右下 \((400, 400)\) に向かって一定速度で移動し、右下隅まで到達すると再び左上に戻るプログラムのソースコードを見てみましょう。

import pygame

# 1. Pygame の初期化とウィンドウの作成
pygame.init()
WIDTH, HEIGHT = 400, 400
screen = pygame.display.set_mode((WIDTH, HEIGHT))
pygame.display.set_caption("Moving Circle")
clock = pygame.time.Clock()

# 円の初期位置（左上）と移動速度・半径の設定
x, y = 0, 0
speed = 3
radius = 20

# 2. メインループ（アニメーションの繰り返し）
running = True
while running:
    # ① イベント処理（ウィンドウの「×」ボタンが押されたら終了する）
    for event in pygame.event.get():
        if event.type == pygame.QUIT:
            running = False

    # ② 円の座標を一定速度で右下へ進める
    x += speed
    y += speed

    # 右下隅まで到達したら左上 (0, 0) に戻す
    if x > WIDTH and y > HEIGHT:
        x, y = 0, 0

    # ③ 画面の描画（背景を白で塗りつぶしてから、青い円を描く）
    screen.fill((255, 255, 255))  # RGBで白色 (255, 255, 255)
    pygame.draw.circle(screen, (30, 136, 229), (x, y), radius)

    # ④ 描画内容を画面に反映し、1秒間に60回（60 FPS）のペースに保つ
    pygame.display.flip()
    clock.tick(60)

# 3. Pygame の終了処理
pygame.quit()

7.8.3.1 コードの重要ポイント

  1. ウィンドウと時計の準備:
    • pygame.display.set_mode((WIDTH, HEIGHT)) で横400ピクセル・縦400ピクセルのウィンドウを作成します。
    • clock = pygame.time.Clock() はアニメーションの速度（フレームレート）を一定に保つためのタイマーです。ループの最後で clock.tick(60) を呼ぶことで、コンピュータの性能にかかわらず「1秒間に60回」のペースでループが回るように調整されます。
  2. 色の指定（RGB形式）:
    • Pygame では色を (赤, 緑, 青) の3つの数値（それぞれ 0〜255）の組み合わせ（RGB）で指定します。(255, 255, 255) は白色、(0, 0, 0) は黒色、(30, 136, 229) は鮮やかな青色を表します。
  3. 毎フレーム screen.fill() で背景を塗りつぶす理由:
    • 新しい位置に円を描く前に screen.fill((255, 255, 255)) で画面全体を白く塗りつぶしています。もしこれを行わないと、1フレーム前に描いた円が画面に残り続け、円が移動するのではなく「青い太線」が伸びていくような表示になってしまいます。
  4. 円の描画と画面への反映:
    • pygame.draw.circle(描画先, 色, (中心x, 中心y), 半径) で円を描き、最後に pygame.display.flip() を呼ぶことで、裏側で描いた絵が実際のウィンドウ画面にパッと反映されます。

  • 強化学習のフレームワークとマルコフ性: 強化学習は「エージェント」と「環境」が状態 \(S_t\)・行動 \(A_t\)・報酬 \(R_{t+1}\) をやり取りしながら状態を変化させていく枠組みであり、次の状態が生じる確率が直前の状態と行動のみに依存するマルコフ性を前提とする。
  • 状態・行動・報酬: エージェントが置かれている状況を表す状態（エピソード終了となる終端状態を含む）、各状態で選べる選択肢である行動、および1ステップごとの評価を与える報酬の3要素によって環境が定義される。
  • 方策と収益（割引率 \(\gamma\)）: エージェントの行動ルールを方策 \(\pi\)、将来にわたって得られる報酬の累積和を収益 \(G_t\) と呼ぶ。割引率 \(\gamma\)（\(0 \le \gamma < 1\)）を導入して \(G_t = R_{t+1} + \gamma R_{t+2} + \gamma^2 R_{t+3} + \dots\) と定義することで、無限に続く経路でも収益が発散せず有限の値として計算・比較できるようになる。
  • 確率的な状態遷移と確率的な方策: スリップなどで移動結果が確定しない確率的な状態遷移や、探索などのために行動を確率的に選ぶ確率的な方策 \(\pi(a \mid s)\)（およびその両方の組み合わせ）では、「① 方策による行動選択」と「② 環境による状態遷移」の2段階の枝分かれを経て次の状態が決まり、同じ方策でも試行ごとにたどる経路や収益 \(G_0\) が確率的に変化する。
  • vibe coding と Pygame によるアニメーション可視化: 3マス移動問題のシミュレーションを vibe coding で構築し、文字による経路・収益の確認から、2Dアニメーションライブラリ Pygame（左上隅を原点 \((0, 0)\) とし、メインループで座標更新と再描画を繰り返す仕組み）を用いたアニメーション表示へと拡張することで、エージェントの振る舞いと収益の変化を視覚的に観察した。

時間 $t = 0, 1, 2, \dots$ において：

1. エージェントは現在の環境の**状態 $S_t$** を観測する。
2. エージェントは方策に基づいて**行動 $A_t$** を決定し実行する。
3. 環境は行動を受けて状態を更新し、新しい**状態 $S_{t+1}$** と即時**報酬 $R_{t+1}$** をエージェントに返す（そして $S_{t+1}$ が次のステップの現在の状態となり、対話が繰り返される）。

### マルコフ性（Markov Property）

上の図の下段にあるように、ステップ $t = 0, 1, 2, \dots$ と進むにつれて状態は連鎖的に変化していきますが、この強化学習のフレームワークには**マルコフ性（Markov Property）**という重要な前提があります。

**マルコフ性とは**
「次の状態 $S_{t+1}$（および報酬 $R_{t+1}$）が生じる確率は、**直前の現在の状態 $S_t$ と行動 $A_t$ のみ**に依存し、それ以前の過去の履歴には一切依存しない」という性質です。

たとえば迷路の移動やボードゲームにおいて、「いまどのマスにいるか・いま盤面がどうなっているか（現在の状態 $S_t$）」さえ分かれば、そこに至るまでにどのような経路や手順をたどってきたか（過去の経緯）を記憶していなくても、将来の予測や最適な行動決定を行うことができます。このようにマルコフ性を満たす環境における意思決定の枠組みを**マルコフ決定過程（MDP: Markov Decision Process）**と呼びます。

## 状態・行動・報酬

### 状態（State: $S$）
エージェントが現在置かれている状況や局面の情報です（一般的にはマップ上の座標、盤面の駒の配置、ロボットの角度や速度などが該当します）。

- **3マスの例における「状態」**:
  エージェントが**どのマスに居るか**が状態であり、左のマスから順に **$\text{A}, \text{B}, \text{C}$** の3つの状態が存在します。
  - **状態 $\text{A}$（左のマス）・状態 $\text{B}$（中央のマス）**: エージェントがこれから行動を選択する通常の状態です。
  - **状態 $\text{C}$（右のマス）**: ここに到達すると1回分のプレイ（**エピソード**）が終了します。このような終了地点の状態を**終端状態（Terminal State）**と呼びます。
  - **時刻 $t$ の状態 $S_t$ との関係**: $S_t$（$S_0, S_1, S_2, \dots$）は「ステップ $t$ の時点でどの状態にいるか」を表す変数であり、その中身（値）として $\text{A}, \text{B}, \text{C}$ が入ります。たとえば「時刻 $t=0$ にマス $\text{A}$ からスタートし、時刻 $t=1$ にマス $\text{B}$ へ移動した」場合、**$S_0 = \text{A},\; S_1 = \text{B}$** と表されます。

### 行動（Action: $A$）
エージェントが各状態において取ることができる選択肢です。

- **3マスの例における「行動」**:
  エージェントが選べる行動は **`Right`（右のマスへ移動）** と **`Left`（左のマスへ移動）** の2種類です。選ぶ行動によって、次の状態が以下のように変化します：
  - 状態 **$\text{A}$** のとき：`Right` を選ぶと **$\text{B}$** へ移動します。`Left` を選ぶとこれ以上左にマスがないため、壁に阻まれて **$\text{A}$** に留まります（例：$S_0 = \text{A}$ で $A_0 = \text{Left}$ を選ぶと、次の時刻も $S_1 = \text{A}$ となります）。
  - 状態 **$\text{B}$** のとき：`Right` を選ぶと **$\text{C}$** へ移動し、`Left` を選ぶと **$\text{A}$** へ戻ります。
  - 状態 **$\text{C}$** のとき：$\text{C}$ に到達した時点でエピソード終了となるため、**$\text{C}$ からの行動は定義されません**。

### 報酬（Reward: $R$）
行動の結果として環境からエージェントに与えられる即時の数値的な評価です。エージェントにとっての「ご褒美（プラス値）」や「ペナルティ・コスト（マイナス値）」を表します。

- **3マスの例における「報酬」**:
  次の2つのルールで報酬が与えられます：
  1. **1回の行動につき $-1$**：`Right` または `Left` を1回実行するたびに、移動コスト（時間経過のペナルティ）として **$-1$** が与えられます。もしこの $-1$ がなければ、エージェントは何百回も左右にウロウロしてからゴールしても損をしないことになりますが、1手ごとに $-1$ されることで**「できるだけ少ない手数（最短経路）でゴールする」**ことが促されます。
  2. **$\text{C}$ に到達したとき $+10$**：ゴールである $\text{C}$ に到達したときに、目標達成のご褒美として **$+10$** が与えられます。
  - したがって、各行動をとった直後に得られる報酬は、通常の移動（$\text{A} \to \text{B}$ や $\text{B} \to \text{A}$、$\text{A} \to \text{A}$）では **$-1$** となり、$\text{B}$ から `Right` を選んで **$\text{C}$ に到達したステップでは、1回分の行動に対する $-1$ と $\text{C}$ 到達の $+10$ を合わせて $-1 + 10 = +9$** となります。

## 方策と収益

「状態・行動・報酬」という環境のルールが定まったところで、次はエージェント側の「行動の選び方（**方策**）」と、その良し悪しを測る「獲得報酬の合計（**収益**）」について見ていきましょう。

### 方策（Policy: $\pi$）
エージェントが「どの状態において、どの行動を選ぶか」を定めた**行動のルール（戦略）**を**方策（Policy）**と呼び、ギリシャ文字の $\pi$（パイ）で表します。

ここでは、各状態 $s$ に対して取るべき行動 $a$ がただ1つに決まっている**決定的方策（Deterministic Policy）**を考えます。数式では関数のように次のように表します：

$$
a = \pi(s)
$$

先ほどの3マスの移動問題では、行動を選択する状態は $\text{A}$ と $\text{B}$ の2つ（状態 $\text{C}$ はエピソード終了のため行動なし）であり、それぞれ `Right` か `Left` を選べるため、決定的方策は全部で $2 \times 2 = 4$ 通り存在します。

### 収益（Return: $G_t$）と方策ごとの計算例
強化学習におけるエージェントの目的は、目の前の1ステップの報酬だけではなく、**エピソード終了までに将来にわたって得られる報酬の総和**を最大化することです。この累積報酬を**収益（Return）**と呼び、$G_t$ で表します。

まずは割引を考えない単純な報酬の足し算（$G_0 = R_1 + R_2 + R_3 + \dots$）として、代表的な2つの方策で**状態 $\text{A}$ からスタート（$S_0 = \text{A}$）したときの収益 $G_0$** を計算してみましょう。

#### 状態 $\text{A}, \text{B}$ で `Right` という方策のとき
状態 $\text{A}$ でも状態 $\text{B}$ でも常に `Right` を選ぶ方策（$\pi(\text{A}) = \text{Right},\; \pi(\text{B}) = \text{Right}$）に従い、状態 $\text{A}$（$S_0 = \text{A}$）からスタートします。

1. **1ステップ目（$t = 0 \to 1$）**：状態 $\text{A}$ で `Right` を選び、状態 $\text{B}$（$S_1 = \text{B}$）へ移動します。1回の行動につき $-1$ の報酬が与えられるため、**$R_1 = -1$** です。
2. **2ステップ目（$t = 1 \to 2$）**：状態 $\text{B}$ で `Right` を選び、状態 $\text{C}$（$S_2 = \text{C}$）へ到達します。行動1回分の $-1$ と状態 $\text{C}$ 到達の $+10$ により **$R_2 = -1 + 10 = +9$** を得て、ここで**エピソード終了**となります。

したがって、単純に報酬を足し合わせた場合の収益 $G_0$ は次のようになります：

$$
G_0 = R_1 + R_2 = (-1) + 9 = +8
$$

#### 状態 $\text{A}, \text{B}$ で `Left` という方策のとき
次に、状態 $\text{A}$ でも状態 $\text{B}$ でも常に `Left` を選ぶ方策（$\pi(\text{A}) = \text{Left},\; \pi(\text{B}) = \text{Left}$）に従い、同じく状態 $\text{A}$（$S_0 = \text{A}$）からスタートしてみます。

1. **1ステップ目（$t = 0 \to 1$）**：状態 $\text{A}$ で `Left` を選びますが、左端の壁に阻まれて状態 $\text{A}$（$S_1 = \text{A}$）に留まります。報酬は **$R_1 = -1$** です。
2. **2ステップ目（$t = 1 \to 2$）**：再び状態 $\text{A}$ にいるため、方策に従ってまた `Left` を選び、状態 $\text{A}$（$S_2 = \text{A}$）に留まって報酬 **$R_2 = -1$** を得ます。
3. **3ステップ目以降**：この後も永久に状態 $\text{A}$ で `Left` を選び続け、いつまでも状態 $\text{C}$ に到達しないため、**エピソードが永遠に終わりません**。

このとき、報酬を単純に足し合わせようとすると、

$$
G_0 = R_1 + R_2 + R_3 + \dots = (-1) + (-1) + (-1) + \dots = -\infty
$$

となり、**収益が無限大（$-\infty$）に発散**してしまいます。収益が発散してしまうと、方策どうしの良し悪しを数値として比較したり計算したりすることができなくなります。

### 割引率（Discount Factor: $\gamma$）の導入
このようにエピソードが無限に続く場合でも**収益が発散することを防ぎ、有限の数値として計算できるようにする**ために導入されるのが**割引率（Discount Factor）$\gamma$**（ガンマ、$0 \le \gamma < 1$）です。

将来の報酬ほど時間経過に伴って価値が割り引かれると考え、1ステップ先になるごとに報酬に $\gamma$ を掛け合わせて**収益 $G_t$** を定義します：

$$
G_t = R_{t+1} + \gamma R_{t+2} + \gamma^2 R_{t+3} + \dots = \sum_{k=0}^{\infty} \gamma^k R_{t+k+1}
$$

> **直感的理解**: 今すぐもらえる100円と、遠い将来にもらえる100円では現在の価値が異なるのと同じです。$\gamma$ が $0$ に近いと「目先の報酬だけを重視」し、$\gamma$ が $1$ に近い（通常 $0.9 \sim 0.99$）と「将来の報酬も重視」します。

### 割引率 $\gamma = 0.9$ で収益を計算してみる
それでは、割引率を **$\gamma = 0.9$** に設定して、先ほどの2つの方策で状態 $\text{A}$ からスタートしたときの収益 $G_0$ を改めて計算してみましょう。

#### 状態 $\text{A}, \text{B}$ で `Right` という方策（$\gamma = 0.9$）
2ステップでゴールに到達して終了するため、項は $R_1 = -1$ と $R_2 = +9$ の2つだけです。2ステップ目の報酬 $R_2$ に $\gamma = 0.9$ が1回掛けられます：

$$
G_0 = R_1 + \gamma R_2 = (-1) + 0.9 \times 9 = -1 + 8.1 = \mathbf{7.1}
$$

#### 状態 $\text{A}, \text{B}$ で `Left` という方策（$\gamma = 0.9$）
毎ステップ $R_1 = -1,\; R_2 = -1,\; R_3 = -1, \dots$ が無限に続きますが、1ステップごとに $0.9$ 倍ずつ割り引かれるため、発散せずに有限の値に収束します：

$$
\begin{aligned}
G_0 &= R_1 + \gamma R_2 + \gamma^2 R_3 + \gamma^3 R_4 + \dots \\
&= (-1) + 0.9 \times (-1) + 0.9^2 \times (-1) + 0.9^3 \times (-1) + \dots \\
&= (-1) \times \left(1 + 0.9 + 0.9^2 + 0.9^3 + \dots \right)
\end{aligned}
$$

ここで、カッコの中身は初項 $1$・公比 $0.9$ の無限等比級数（$1 + \gamma + \gamma^2 + \dots = \dfrac{1}{1 - \gamma}$）なので、

$$
G_0 = (-1) \times \frac{1}{1 - 0.9} = (-1) \times \frac{1}{0.1} = \mathbf{-10}
$$

と求めることができます。

::: {.callout-tip icon=true}
### 別解：再帰的な関係式を使って求める方法
無限等比級数の公式を覚えていなくても、次のような工夫で簡単に計算できます。
$G_0$ の式の2項目以降を $0.9$ でくくると、カッコの中身は元の $G_0$ とまったく同じ形になります：

$$
\begin{aligned}
G_0 &= -1 + 0.9 \times \underbrace{\left( -1 + 0.9 \times (-1) + 0.9^2 \times (-1) + \dots \right)}_{=\, G_0} \\
G_0 &= -1 + 0.9\, G_0
\end{aligned}
$$

この1次方程式を解くと、$0.1\, G_0 = -1$ より **$G_0 = -10$** がすぐに得られます。「現在の収益 ＝ 直後の報酬 ＋ $\gamma \times$ 次のステップからの収益」というこの関係は、強化学習において極めて重要な性質です。
:::

## 確率的な状態遷移

これまでの説明では、状態 $\text{A}$ で `Right` を選べば **100%確実に** 状態 $\text{B}$ へ移動できるように、「現在の状態と行動が決まれば、次の状態がただ1つに確定する」という前提で考えてきました。このような環境を**決定的（Deterministic）**な環境と呼びます。

しかし、現実世界や多くのゲーム環境では、エージェントが意図したとおりに100%確実に移動できるとは限りません。

- 車輪ロボットが前進しようとしても、床が濡れていて**その場でスリップ（空回り）してしまう**。
- ドローンや自動運転車が、突風や路面の状況によって**意図した位置へ進めない**。
- ゲームにおいて、氷の上を歩くキャラクターが**一定の確率で滑ってその場にとどまったり、別の方向へ流されたりする**。

このように、ある状態で行動を実行したとき、次の状態が確率的に決まる仕組みを**確率的な状態遷移（Stochastic State Transition）**と呼びます。

::: {.callout-tip icon=true}
### 確率的な状態遷移でも「マルコフ性」は成り立つ
状態遷移が確率的であっても、「次の状態 $S_{t+1}$ がどの状態になるかの**確率**」が**直前の状態 $S_t$ と行動 $A_t$ のみ**によって決まり、それ以前の過去の履歴に依存しないならば、マルコフ性は満たされています。
:::

#### 経路パターン1：1度も滑らずに2ステップでゴールする場合（$\text{A} \to \text{B} \to \text{C}$）
- **1ステップ目（$t = 0 \to 1$）**：状態 $\text{A}$ で `Right` を選び、**80%（$0.8$）**の確率で状態 $\text{B}$ へ移動します（$R_1 = -1$）。
- **2ステップ目（$t = 1 \to 2$）**：状態 $\text{B}$ で `Right` を選び、**80%（$0.8$）**の確率で状態 $\text{C}$ へ到達して終了します（$R_2 = +9$）。
- **この経路をたどる確率**：
  $$
  0.8 \times 0.8 = 0.64 \quad (\mathbf{64\%})
  $$
- **このときの収益 $G_0$**：
  $$
  G_0 = R_1 + \gamma R_2 = (-1) + 0.9 \times 9 = \mathbf{7.1}
  $$

#### 経路パターン2：最初に状態 $\text{A}$ で1回とどまり、3ステップでゴールする場合（$\text{A} \to \text{A} \to \text{B} \to \text{C}$）
- **1ステップ目（$t = 0 \to 1$）**：状態 $\text{A}$ で `Right` を選びますが、**20%（$0.2$）**の確率で滑って状態 $\text{A}$ にとどまります（$R_1 = -1$）。
- **2ステップ目（$t = 1 \to 2$）**：再び状態 $\text{A}$ で `Right` を選び、今度は**80%（$0.8$）**の確率で状態 $\text{B}$ へ移動します（$R_2 = -1$）。
- **3ステップ目（$t = 2 \to 3$）**：状態 $\text{B}$ で `Right` を選び、**80%（$0.8$）**の確率で状態 $\text{C}$ へ到達して終了します（$R_3 = +9$）。
- **この経路をたどる確率**：
  $$
  0.2 \times 0.8 \times 0.8 = 0.128 \quad (\mathbf{12.8\%})
  $$
- **このときの収益 $G_0$**：1ステップ余計にかかったため、移動コスト $-1$ が増えるとともに、ゴール時の報酬 $+9$ が $\gamma^2 = 0.9^2 = 0.81$ 倍に割り引かれます：
  $$
  G_0 = R_1 + \gamma R_2 + \gamma^2 R_3 = (-1) + 0.9 \times (-1) + 0.9^2 \times 9 = -1 - 0.9 + 7.29 = \mathbf{5.39}
  $$

このように、確率的な状態遷移をもつ環境では、**同じ方策 $\pi$ に従っていても、1回のエピソードで得られる収益 $G_t$ は試行ごとに異なる値（確率変数）**になります。

## 確率的な方策

前節では「環境側の状態遷移」が確率的になる場合を見ましたが、エージェント側の行動ルールである**「方策（Policy）」そのものが確率的になる**場合もあります。

「方策と収益」の節では、各状態 $s$ に対して取るべき行動が $a = \pi(s)$ のようにただ1つに決まっている**決定的方策（Deterministic Policy）**を扱いました。これに対し、「ある状態 $s$ にいるとき、各行動 $a$ をそれぞれどのくらいの確率で選ぶか」を定めた方策を**確率的方策（Stochastic Policy）**と呼び、状態 $s$ で行動 $a$ を選ぶ確率を次のように表します：

$$
\pi(a \mid s)
$$

たとえば、状態 $\text{A}$ において `Right` を選ぶ確率と `Left` を選ぶ確率がそれぞれ $50\%$（$0.5$）である場合、$\pi(\text{Right} \mid \text{A}) = 0.5,\; \pi(\text{Left} \mid \text{A}) = 0.5$ と表します（同じ状態で選びうるすべての行動の選択確率を足し合わせると必ず $1$ になります）。

::: {.callout-tip icon=true}
### なぜ確率的な方策を使うのか？
1. **探索（Exploration）を行うため**：前章の多腕バンディット問題で学んだ $\varepsilon$-greedy 法のように、未知の状況を試してより良い経路を発見するためには、一定の確率でランダムに行動を選ぶ必要があります。特に学習開始時は、まだどの行動が良いか分からないため、**完全にランダムに行動を選ぶ方策**からスタートするのが一般的です。
2. **対戦ゲームなどで裏をかくため**：じゃんけんやカードゲームのように相手がいる環境では、いつも同じ行動をとる決定的方策だと相手に先読みされてしまうため、確率的に行動を散らす方策が有効になります。
:::

  $$
  0.5 \times 0.5 = 0.25 \quad (\mathbf{25\%})
  $$
- **このときの収益 $G_0$**：
  $$
  G_0 = R_1 + \gamma R_2 = (-1) + 0.9 \times 9 = \mathbf{7.1}
  $$

#### 経路パターン2：最初に状態 $\text{A}$ で `Left` を選び、3ステップでゴールする場合（$\text{A} \to \text{A} \to \text{B} \to \text{C}$）

  $$
  0.5 \times 0.5 \times 0.5 = 0.125 \quad (\mathbf{12.5\%})

## 確率的な状態遷移と確率的な方策

ここまでの2つの節では、「環境の状態遷移だけが確率的な場合（方策は決定的）」と「エージェントの方策だけが確率的な場合（環境は決定的）」をそれぞれ個別に見てきました。

しかし、実際の強化学習では**「環境の状態遷移が確率的」であり、かつ「エージェントの方策も確率的」**という状況がごく一般的に現れます。たとえば、滑りやすい床や風が吹く環境の中で、エージェントが未知の状況を探索するためにランダム性を交えて行動を選択する場合などがこれにあたります。

このように両方とも確率的である場合、現在の状態 $S_t$ から次の状態 $S_{t+1}$ が決まるまでに、次の**2段階の確率的な枝分かれ**が順番に起こります：

1. **第1段階（エージェントの方策 $\pi$）**：現在の状態 $S_t$ において、エージェントが確率的方策 $\pi(a \mid s)$ に従って**行動 $A_t$ を確率的に選ぶ**。
2. **第2段階（環境の状態遷移）**：選ばれた行動 $A_t$ に対して、環境が状態遷移確率に従って**次の状態 $S_{t+1}$（と報酬 $R_{t+1}$）を確率的に決める**。

### 状態 $\text{A}$ から次の状態が決まる様子

上の枝分かれの図を左から順にたどると、各枝の確率と最終的な次の状態 $S_{t+1}$ の確率は次のように計算できます：

1. **行動 `Right`（選択確率 $50\% = 0.5$）を選んだ場合**：
   - **80%（$0.8$）で移動に成功**：次の状態は **$S_{t+1} = \text{B}$**（報酬 $R_{t+1} = -1$）となります。この枝をたどる確率は、行動を選ぶ確率と状態遷移の確率を掛け合わせて
     $$
     0.5 \times 0.8 = 0.40 \quad (\mathbf{40\%})
     $$
   - **20%（$0.2$）でスリップ**：次の状態は **$S_{t+1} = \text{A}$**（報酬 $R_{t+1} = -1$）のままとなります。この枝をたどる確率は
     $$
     0.5 \times 0.2 = 0.10 \quad (\mathbf{10\%})
     $$

2. **行動 `Left`（選択確率 $50\% = 0.5$）を選んだ場合**：
   - 左に動こうとして壁に阻まれる場合（$80\%$）も、スリップする場合（$20\%$）も、どちらも次の状態は **$S_{t+1} = \text{A}$**（報酬 $R_{t+1} = -1$）となります。したがって、`Left` を選んで状態 $\text{A}$ に留まる確率は
     $$
     0.5 \times 0.8 + 0.5 \times 0.2 = 0.40 + 0.10 = 0.50 \quad (\mathbf{50\%})
     $$
     （最初から「`Left` を選べば $100\%$（$1.0$）の確率で $\text{A}$ に留まる」と考えて $0.5 \times 1.0 = 0.50$ と計算しても同じです。）

3. **次の状態 $S_{t+1}$ ごとに確率をまとめる**：
   注目すべき点は、**「`Right` を選んだけれどスリップしたケース（$10\%$）」**と**「`Left` を選んで留まったケース（$50\%$）」**という異なる枝から、どちらも同じ**状態 $\text{A}$** に到達していることです。これらを足し合わせると、状態 $\text{A}$ から1ステップ進んだ後の状態 $S_{t+1}$ の確率分布は次のようになります：
   - **状態 $\text{B}$ へ進む確率**：**$40\%$**（$0.4$）
   - **状態 $\text{A}$ に留まる確率**：$10\% + 50\% = \mathbf{60\%}$（$0.6$）

### エピソード全体の経路の確率と収益 $G_0$

同様に、中央の**状態 $\text{B}$** にいるときも「① 行動の選択（`Right` $50\%$ ／ `Left` $50\%$）」と「② 環境の状態遷移（移動成功 $80\%$ ／ スリップ $20\%$）」の2段階の枝分かれが起こります。たとえば状態 $\text{B}$ から1ステップでゴール（状態 $\text{C}$）へ到達するには、状態 $\text{B}$ で `Right`（$50\%$）を選び、かつ滑らずに移動（$80\%$）する必要があるため、その確率は $0.5 \times 0.8 = 0.40$（**$40\%$**）となります。

これを使うと、状態 $\text{A}$ からスタート（$S_0 = \text{A}$）したときの各経路の確率と収益 $G_0$（割引率 $\gamma = 0.9$）もこれまでと同じように計算できます：

- **最短の2ステップでゴールする場合（$\text{A} \to \text{B} \to \text{C}$）**：
  - 1ステップ目に $\text{A} \to \text{B}$ となる確率が **$40\%$（$0.4$）**、2ステップ目に $\text{B} \to \text{C}$ となる確率も **$40\%$（$0.4$）** なので、この経路をたどる確率は
    $$
    0.4 \times 0.4 = 0.16 \quad (\mathbf{16\%})
    $$
  - 収益はこれまでと同じく $G_0 = (-1) + 0.9 \times 9 = \mathbf{7.1}$ です。

- **最初に状態 $\text{A}$ に1回留まり、3ステップでゴールする場合（$\text{A} \to \text{A} \to \text{B} \to \text{C}$）**：
  - 1ステップ目に $\text{A} \to \text{A}$ となる確率は、`Right` で滑る確率（$10\%$）と `Left` で留まる確率（$50\%$）を合わせた **$60\%$（$0.6$）** です。その後 $\text{A} \to \text{B}$（$0.4$）、$\text{B} \to \text{C}$（$0.4$）と進むため、合計の確率は
    $$
    0.6 \times 0.4 \times 0.4 = 0.096 \quad (\mathbf{9.6\%})
    $$
  - 収益は $G_0 = (-1) + 0.9 \times (-1) + 0.9^2 \times 9 = \mathbf{5.39}$ です。

## vibe codingによるシミュレーションの作成

ここまで学んだ「3マスの移動問題（確率的な状態遷移 × 確率的な方策）」を、Antigravity（coding agent）を使って **vibe coding** でプログラムとして作成し、実際にエージェントがたどる経路と得られる収益 $G_0$ を確認してみましょう。

### 作成するプログラムの仕様

エージェントには、以下の要件を満たすシミュレーションプログラムを作成してもらいます：

1. **環境（3マスの移動問題・確率的状態遷移）**:
   - 横一列に並んだ3つの状態 $\text{A}, \text{B}, \text{C}$ があり、初期状態は $S_0 = \text{A}$、右端の $\text{C}$ に到達したらエピソード終了（終端状態）とする。
   - エージェントが選んだ方向へ **80%（確率 $0.8$）で移動に成功**し、**20%（確率 $0.2$）でスリップしてその場に留まる**。ただし、状態 $\text{A}$ の左には壁があるため、状態 $\text{A}$ で `Left` を選んだ場合は移動・スリップにかかわらず状態 $\text{A}$ に留まる。
   - 報酬は、行動1回につき **$-1$**、状態 $\text{C}$ に到達したときは **$+10$** が加わる（つまり通常のステップは $-1$、$\text{B}$ から $\text{C}$ に到達したステップは $-1 + 10 = +9$）。
2. **エージェント（確率的方策）**:
   - 状態 $\text{A}$ および状態 $\text{B}$ において、それぞれ **50%（確率 $0.5$）で `Right`**、**50%（確率 $0.5$）で `Left`** をランダムに選ぶ。
3. **文字による経過と結果の表示**:
   - 割引率は $\gamma = 0.9$ とする。
   - 状態 $\text{A}$ からスタートして状態 $\text{C}$ に到達するまでの1エピソードを実行し、各ステップで「ステップ番号」「現在の状態 $S_t$」「選んだ行動 $A_t$」「結果（移動成功／スリップ／壁）と次の状態 $S_{t+1}$」「得られた報酬 $R_{t+1}$」を文字で順番に表示する。

- 報酬は、1回の行動につき `-1`、状態 C に到達したときに `+10` が与えられます（C 到達ステップの報酬は `-1 + 10 = +9`）。

【エージェントの方策と表示内容】
- エージェントは状態 A, B において、50%の確率で `Right`、50%の確率で `Left` を選ぶ確率的方策に従います。
- 割引率は `gamma = 0.9` とします。
- 1エピソードを実行し、各ステップの「現在の状態」「選んだ行動」「移動結果（移動成功・スリップ・壁）と次の状態」「報酬」を1行ずつ文字で表示してください。
- ゴール（状態 C）に到達したら、最後に「たどった経路（例: `A -> B -> C`）」「合計ステップ数」「割引率 0.9 での収益 G_0」を表示してください。
- 作成後、実際にプログラムを数回実行して動作確認を行ってください。

## 2Dゲーム・アニメーションライブラリ Pygame とは？

前節ではターミナル上に文字でエージェントの移動履歴を表示しましたが、強化学習の実験では**エージェントが環境の中で実際にどのように動いているかをアニメーション（映像）として視覚的に確認する**ことが非常に役立ちます。文字だけでは気づきにくい「同じ場所をウロウロしている」「壁にぶつかり続けている」といった振る舞いも、画面上で動いている様子を見れば一目で直感的に把握できます。

Pythonで2Dゲームやアニメーションを手軽に作成・描画できる代表的な外部ライブラリが **Pygame（パイゲーム）** です。

- **Pygame でできること**:
  専用のウィンドウを開き、円や四角形などの図形・テキスト・画像を自由な位置に描画して、1秒間に何十回も画面を書き換えることで滑らかなアニメーションを実現できます。キーボードやマウスの操作を受け取ることも可能です。
- **強化学習との関わり**:
  第8回以降で使用する強化学習の標準ライブラリ **Gymnasium** でも、内部で環境の画面描画（レンダリング）を行うために Pygame が広く使われています。

### Pygame の画面座標系とアニメーションの仕組み

### 基本的な使い方（円が左上から右下へ移動する例）

簡単な例として、**青い円が画面の左上 $(0, 0)$ から右下 $(400, 400)$ に向かって一定速度で移動し、右下隅まで到達すると再び左上に戻るプログラム**のソースコードを見てみましょう。

```python
import pygame

# 1. Pygame の初期化とウィンドウの作成
pygame.init()
WIDTH, HEIGHT = 400, 400
screen = pygame.display.set_mode((WIDTH, HEIGHT))
pygame.display.set_caption("Moving Circle")
clock = pygame.time.Clock()

# 円の初期位置（左上）と移動速度・半径の設定
x, y = 0, 0
speed = 3
radius = 20

# 2. メインループ（アニメーションの繰り返し）
running = True
while running:
    # ① イベント処理（ウィンドウの「×」ボタンが押されたら終了する）
    for event in pygame.event.get():
        if event.type == pygame.QUIT:
            running = False

    # ② 円の座標を一定速度で右下へ進める
    x += speed
    y += speed

    # 右下隅まで到達したら左上 (0, 0) に戻す
    if x > WIDTH and y > HEIGHT:
        x, y = 0, 0

    # ③ 画面の描画（背景を白で塗りつぶしてから、青い円を描く）
    screen.fill((255, 255, 255))  # RGBで白色 (255, 255, 255)
    pygame.draw.circle(screen, (30, 136, 229), (x, y), radius)

    # ④ 描画内容を画面に反映し、1秒間に60回（60 FPS）のペースに保つ
    pygame.display.flip()
    clock.tick(60)

# 3. Pygame の終了処理
pygame.quit()
```

#### コードの重要ポイント

1. **ウィンドウと時計の準備**:
   - `pygame.display.set_mode((WIDTH, HEIGHT))` で横400ピクセル・縦400ピクセルのウィンドウを作成します。
   - `clock = pygame.time.Clock()` はアニメーションの速度（フレームレート）を一定に保つためのタイマーです。ループの最後で `clock.tick(60)` を呼ぶことで、コンピュータの性能にかかわらず「1秒間に60回」のペースでループが回るように調整されます。
2. **色の指定（RGB形式）**:
   - Pygame では色を `(赤, 緑, 青)` の3つの数値（それぞれ `0`〜`255`）の組み合わせ（**RGB**）で指定します。`(255, 255, 255)` は白色、`(0, 0, 0)` は黒色、`(30, 136, 229)` は鮮やかな青色を表します。
3. **毎フレーム `screen.fill()` で背景を塗りつぶす理由**:
   - 新しい位置に円を描く前に `screen.fill((255, 255, 255))` で画面全体を白く塗りつぶしています。もしこれを行わないと、1フレーム前に描いた円が画面に残り続け、円が移動するのではなく「青い太線」が伸びていくような表示になってしまいます。
4. **円の描画と画面への反映**:
   - `pygame.draw.circle(描画先, 色, (中心x, 中心y), 半径)` で円を描き、最後に `pygame.display.flip()` を呼ぶことで、裏側で描いた絵が実際のウィンドウ画面にパッと反映されます。

1. **画面レイアウト（3つのマスと壁の描画）**:
   - Pygame ウィンドウの中央に、横一列に並んだ3つのマス（左から **状態 $\text{A}$**、**状態 $\text{B}$**、**状態 $\text{C}$（ゴール）**）と、状態 $\text{A}$ の左端にある「壁」を描画する。

### アニメーションから確認できること

修正されたプログラムを実行すると、ウィンドウが開いてエージェント（青い円）がステップごとに動いていきます。スペースキー（または `R` キー）で何度もエピソードをやり直しながら観察すると、次のことが視覚的に実感できます：

- **2種類の「その場に留まる動き」の違い**:
  文字で `A -> A` とだけ書かれているとどちらも同じに見えますが、アニメーションで見ると**「右（状態 $\text{B}$）へ進もうとして滑って戻されたのか（`Right`＋スリップ）」**、それとも**「左を選んで壁にぶつかって戻されたのか（`Left`）」**が動きの方向で明確に区別できます。
- **手数が増えることによる収益 $G_0$ の減少**:
  エージェントが途中でスリップしたり、状態 $\text{B}$ から `Left` を選んで状態 $\text{A}$ に逆戻りしたりして時間をかけるほど、$-1$ のペナルティが積み重なり、最後に状態 $\text{C}$ に到達したときの報酬 $+9$ も $\gamma^k$ で大きく割り引かれてしまう様子がリアルタイムに確認できます。

## まとめ

- **強化学習のフレームワークとマルコフ性**: 強化学習は「エージェント」と「環境」が状態 $S_t$・行動 $A_t$・報酬 $R_{t+1}$ をやり取りしながら状態を変化させていく枠組みであり、次の状態が生じる確率が直前の状態と行動のみに依存する**マルコフ性**を前提とする。
- **状態・行動・報酬**: エージェントが置かれている状況を表す**状態**（エピソード終了となる**終端状態**を含む）、各状態で選べる選択肢である**行動**、および1ステップごとの評価を与える**報酬**の3要素によって環境が定義される。
- **方策と収益（割引率 $\gamma$）**: エージェントの行動ルールを**方策 $\pi$**、将来にわたって得られる報酬の累積和を**収益 $G_t$** と呼ぶ。**割引率 $\gamma$**（$0 \le \gamma < 1$）を導入して $G_t = R_{t+1} + \gamma R_{t+2} + \gamma^2 R_{t+3} + \dots$ と定義することで、無限に続く経路でも収益が発散せず有限の値として計算・比較できるようになる。
- **確率的な状態遷移と確率的な方策**: スリップなどで移動結果が確定しない**確率的な状態遷移**や、探索などのために行動を確率的に選ぶ**確率的な方策 $\pi(a \mid s)$**（およびその両方の組み合わせ）では、「① 方策による行動選択」と「② 環境による状態遷移」の2段階の枝分かれを経て次の状態が決まり、同じ方策でも試行ごとにたどる経路や収益 $G_0$ が確率的に変化する。
- **vibe coding と Pygame によるアニメーション可視化**: 3マス移動問題のシミュレーションを vibe coding で構築し、文字による経路・収益の確認から、2Dアニメーションライブラリ **Pygame**（左上隅を原点 $(0, 0)$ とし、メインループで座標更新と再描画を繰り返す仕組み）を用いたアニメーション表示へと拡張することで、エージェントの振る舞いと収益の変化を視覚的に観察した。
